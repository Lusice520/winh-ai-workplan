# WI-008 页面设计基线

使用 2026-09-12 安装的 draw-ui，配合宿主内置 imagegen 生成一张售前工作区设计基线，再沿用到客户、商机和需求池。设计图中的样例均为虚构，不进入正式数据库。

用户在本系统完成客户建档、商机行动、售前协作和需求处理。第一眼应看见“当前对象、当前状态、下一件可执行的事”。桌面逻辑视口 1440×1000，白色 236px 导航和 58px 顶栏沿用现有外壳。主要信息由宽内容区承载，右侧较窄的责任与评审栏辅助决策；不使用大图、宣传语或与工作无关的装饰。

颜色复用现有 Theme：画布 #f5f7fb，白色内容，标题 #182235，正文次级 #667085，主操作 #3157d5，成功 #188b79，警告 #d27632。中文使用本机 PingFang SC / Microsoft YaHei，标题 24–28px，节标题 16px，正文 14px，辅助 12px；数字用等宽数字特性。细边线、8/16/24 间距，圆角 10/14px。状态始终附文字。

售前详情首屏：回到售前项目 → 项目编号与名称 → 主阶段、重点、项目状态、业务结果四项并列 → 项目页签 → 七项规定动作的清晰行列表（状态、责任人、目标时间、成果）→ 右侧 SG-01 与 SG-02 评审依据、投入摘要和关键责任。主要操作为登记成果/更新动作，项目尚未立项时为提交 SG-01；其余按钮由实际状态和服务端返回能力确定。

客户/商机目录使用同一标题、工具栏、细分标签与高密度表格。需求池以状态筛选和记录列表为主，详情抽屉显式呈现原文、澄清与影响评估、处理去向、完成证据和验证；有前置条件时说明缺项。筛选写入 URL；新增、编辑、提交失败保持输入；离开脏表单确认。

390px 时使用原有侧栏 Drawer，项目页头换行，辅助栏移到主栏下方，表格仅在自己的容器内横向滚动；标签支持横向滚动；表单单列，触控区域至少 40px。加载、空态、无结果、请求失败、无权限、冲突、保存中及关闭只读分别实现。

布局、文字、图标、控件、状态和数据均以 React + Ant Design v6 + Lucide 实现；设计图不进入运行页面。真实操作验收和图像视觉检查分别记录。

## 用户密度校正（2026-09-12）

Lusice 要求设计更丰富、相对紧凑、避免大面积空白，同时保持清爽。首屏标题区收紧为 100–130px（不含页签）；四类事实并列为一条紧凑条，表格行高约 48–52px，单元格上下 9–11px，卡片内边距 16px；七项动作首屏可扫描，右栏保留评审、责任、期限、投入和待办，主区补充近期真实活动。避免纯装饰数据卡、空面板和冗长说明，暂无数据使用小型空态与直接操作。保留字体可读性、40px 主要触控区域和窄屏换行，不以缩小正文或塞满色块换取密度。
