# 原项目执行页设计说明

目标：让项目经理和专业负责人快速比较批准计划与实际，定位待核验和未完成事项，并登记阶段/清单事实。沿用 WI-010 已检查的蓝白工作区与侧栏，不改变产品固定入口。

构思：主内容以阶段时间轴和横向计划/实际对照为焦点，下接带细进度条的清单行；右侧较窄的“需要处理”与近期事件提供行动线索。密度来自可读的真实内容和稳定对齐，不靠大标题与大块装饰；数量有统一分母，状态兼具文字和颜色。

视口：桌面逻辑 1522×1033 CSS px，允许下滚；参考图以近 3:2 横幅生成。手机 390×844，导航折叠，摘要紧凑换行、详情单列、表格局部横向滚动。字体沿用系统中文无衬线，正文 14px、辅助 12px、标题 22px；主色 #3478F6、文字 #18335B、次级 #73849E、背景 #F4F7FC、边框 #DFE8F5，8/12/16/24 间距。普通控件/图表/正文全部由代码实现，图片仅作为设计参考。

示例：演示项目、当前交付基线 V4，4 阶段中 1 完成/2 进行中/1 未开始；示例清单控制柜 6 台，到货 6、安装 4、验收 2、待验收 1；其余 3 项不同数量但不超范围。页内标明示例数据。主操作“记录执行”，项目固定页签“项目阶段”选中，可切“项目清单/里程碑”。当前阶段展开专业工作包、计划/实际、完成条件与“登记进展”。

失败/空态：未批准显示来源和缺项；未配置适用环节显示明确动作；冲突保留表单与服务器说明。只读与无权字段按实际 API 呈现，示例不可当作真实完成证据。
