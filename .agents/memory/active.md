# 项目活跃经验

## 文档目录与协作边界

- 记录日期：2026-08-26
- 正式文档采用四层结构：requirements（业务、产品与单功能详细设计）、technical（总体技术方案、ADR 与跨功能共享设计）、development-testing（开发、测试与验收）、history-archive（历史资料）。
- 单功能详细设计统一进入对应 SPEC，不再建立平行 DES；technical/designs 只保存至少两个功能共同遵守或跨工程运行边界的共享设计。
- BRD、PRD、SPEC、ADR 保留通用缩写；目录名使用简明英文，文档标题与正文使用中文。
- 产品流程和交互原型进入 requirements/product-flows；原始附件和参考资料进入 requirements/references。
- 开发任务与需求补充使用 development-testing/work-items；issues 只表示 Bug；测试用例使用 test-cases；验收资料使用 accept。
- AI 协作规则、Hook、脚本和工作上下文不进入 docs：项目入口为根目录 AGENTS.md，项目内部规则和活跃经验位于 .agents/。

## PRD 功能结构表达

- 记录日期：2026-07-23
- 适用范围：`docs/requirements/PRD.md` 及后续各批次 PRD。
- 结构约定：PRD“系统概述—产品功能结构与建设清单”必须按“一级菜单 → 二级菜单 → 功能页面/对象 → 能力编号 → 子功能 → 核心价值 → 批次/优先级”表达，同时反映导航归属和建设范围。
- 合并边界：菜单功能结构与独立功能清单合并维护，不再建立重复章节；项目空间固定入口可在下一小节展开，但能力编号必须能够追溯到需求说明和 SPEC。
- 细化边界：PRD 确定菜单归属和页面层级；菜单排序、页面布局、字段、按钮、完整状态和异常交互进入 SPEC 与原型。

## P1 MVP 商机、售前与 DG-01 范围

- 记录日期：2026-07-16
- “我的商机”暂不作为独立菜单；我负责、我协作、待跟进和逾期等需求并入商机台账的筛选与视图。
- P1 MVP 从客户/商机开始，到 DG-01 通过并形成交付移交包结束；P2 从该移交包接续，先开放团队、执行阶段、项目清单、工作包、计划和预算草案以准备 DG-02，通过后同一对象转为批准基线并切换主阶段；P3 沿用该基线开展完整交付执行，不重复建对象。
- P1 核心包括客户与商机、项目空间公共区、SG-01、并行售前规定动作、SG-02、需求池、资料/分享、业务结果回显、DG-01、提前开工、最小合同归档、分析看板、权限规则和 Excel 一次性迁移。
- 客户作为独立主档进入本系统，商机必须关联明确客户；客户唯一性、数据来源和合并规则进入客户管理 SPEC。
- 售前立项、资源费用审批、调研方案、估算和报价投标协同属于 P1，不再拆为后续 PRD 批次。
- 商机分析与可视化看板是独立二级菜单和独立验收对象；看板按角色呈现，并下钻到客户、商机和售前原始记录。

## 项目空间、阶段与业务结果

- 记录日期：2026-07-23
- 项目空间是贯穿售前、交付和维护的协作容器，不是新增业务对象层级；取消交付单元主对象。
- 项目空间固定入口为：项目概览、项目阶段、里程碑、项目清单、需求池、资金计划、风险管理、问题管理、项目例会、日报周报、成员、项目资料；子功能按批次渐进开放。
- 主阶段、执行阶段、当前重点阶段、项目状态、阶段门、售前规定动作、专业工作包和业务结果必须分开。
- 主阶段为售前、交付、维护；验收是交付内执行阶段；项目状态为待立项、进行中、暂停、已关闭。
- 执行阶段可并行，并指定一个当前重点阶段用于默认回显；阶段模板版本化，项目保留模板快照，运行中项目不被新模板版本静默覆盖。
- 项目经理管理阶段启停、跳过、完成、重开和主阶段；阶段负责人维护本阶段内容但不能改变主阶段。
- 多设备、多现场、采购、到货、安装和验收由项目清单统一管理。
- 业务结果稳定类别至少为待定、成功、失败、客户取消、主动终止；招投标场景显示中标/未中标，非招标场景显示成交/未成交，并在商机、项目台账、空间页头、详情和分析看板同步回显。
- 未中标的标准表达为“售前｜已关闭｜未中标”，不以“已关闭”替代业务结论。
- 售前调研、需求、方案、估算、报价、招投标和技术交底准备是并行、可反复的规定动作，不是项目主阶段或交付工作包。

## 需求、资料、迁移与后续边界

- 记录日期：2026-07-23
- 需求池是项目空间独立入口并贯穿售前、交付和维护；接收商务、售前、交付、客户和项目组需求，可由人员派生/关联问题、工作包、任务或变更，原需求保留。
- 风险管理是独立入口；风险等级、规则、负责人、验证人和派生关系由人员维护，风险发生后由人员手动派生/关联问题。
- 新系统是项目资料查找、分享和过程协作入口；NAS 仅做验收后的长期归档副本。
- 所有文件类型技术上都可生成外网链接＋密码，但生成者必须同时拥有文件查看/下载权限和独立分享权限；首期不增加分享审批，不建设客户/供应商门户。
- 飞书商机表通过 Excel 一次性迁移全部约 30—50 条商机后停用；不迁移附件、评论和跟进历史，也不建设持续同步。
- 提前开工获批可作为限定范围的开工依据，但不自动通过 DG-01；P1 以最小承诺台账记录金额/工时、责任、占用和实际发生，到期、超范围或超预算时冻结新增承诺。
- 实际确认收入是已完成事实，由PMO提交、营销确认；回款计划由营销发布并通知PMO，付款/采购计划由PMO发布，三类计划发布后直接生效并可版本迭代。
- 实际回款由商务/营销维护，实际付款与采购执行由项目经理维护；项目经营台账不替代财务会计核算。
- 售前保留项目资金摘要、风险、问题和成员查看权，但默认不可查看成本、采购价格、利润和内部费率。
- 项目经理每天纯手写项目日报，首期不设提交限制；成员按项目提交周报，系统汇总为项目周报草稿，项目经理补充审核，项目例会关联周报并形成会后待办闭环。
- 里程碑和预算由项目经理调整，填写原因后新版本直接生效，可附线下依据，保留历史版本；首期不做复杂审批。
- 项目关闭流程当前暂缓；自动化项目公司级采购清单库和售前选择性配置放入后续阶段。
- 合同只做签署后主档和归档，不做审批、法务、电子签署、用印或纸质原件管理。
- 绩效管理当前暂缓，未来如需另行讨论。
