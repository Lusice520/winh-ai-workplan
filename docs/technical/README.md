# 技术方案、决策与共享设计

本目录承载“项目全生命周期管理系统”的总体技术方案、关键技术决策记录和跨功能共享设计。单功能详细设计统一进入对应 SPEC，不在这里建立平行 DES。当前已接受 P1 的技术栈、运行形态、员工 VPN 访问、自建账号和前端组件基线；实际环境、容量、灾备与安全运行参数仍需在工程和上线前定标。

## 阅读顺序

1. [总体技术方案 V0.3](./TECHNICAL_SOLUTION.md)：目标、约束、总体架构、已接受基线、上线条件和演进原则。
2. [架构决策记录索引](./adr/README.md)：已接受的 P1 技术选择、替代方案、后果和待建立的 ADR。
3. [跨功能共享设计](./designs/README.md)：多个功能共同遵守的组件、接口、数据、安全和运行规范。
4. [单功能 SPEC](../requirements/specs/SPEC_TEMPLATE.md)：功能需求与页面、接口、数据、实现、测试和验收设计的统一入口。
5. [产品需求文档（PRD）](../requirements/PRD.md)与[业务需求文档（BRD）](../requirements/BRD.md)：正式业务与产品事实。
6. [开发、测试与验收](../development-testing/README.md)：SPEC 进入实施后的计划、任务、测试与验收资料。

## 基线规则

- requirements 是当前需求事实入口；技术文档不得静默改变 PRD、BRD 的范围、业务对象和验收口径。
- development-testing 保存实施资料，不替代技术或需求事实。
- outputs 是导出物、预览或阶段性构建结果，不是正式需求或技术基线。
- history-archive 中的历史兼容资料不作为当前技术基线。
- 技术栈、部署、身份、NAS、容量或非功能指标只有在 ADR 被接受并回写总体技术方案后，才可从“待确认”变为“已确认”。
- 不批量创建空白共享设计；达到跨功能复用条件时才建立，单功能设计始终回到对应 SPEC。
