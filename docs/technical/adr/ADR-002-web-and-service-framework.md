# ADR-002：P1 前端与后端语言框架

> 状态：已接受  
> 日期：2026-08-26  
> 决策人：项目负责人  
> 关联需求：PRD V0.4 的桌面 WEB、移动响应式 WEB、复杂表单表格、权限、文件上传和项目空间要求  
> 关联验证：账号权限、复杂表单、列表筛选、文件上传和响应式页面原型；依赖与安全更新检查

## 背景与问题

系统首期以桌面 WEB 为主要入口，并需支持移动响应式访问。团队更熟悉 Java，公司没有必须继承的前后端技术栈。P1 需要长期维护的事务、权限、文件和后台任务能力，同时不建设原生 APP 或服务器渲染的内容站点。

## 决策驱动因素

- 团队对 Java 的维护和招聘可持续性；
- 业务系统对表格、表单、权限路由、文件上传和可复用组件的要求；
- 前后端职责清晰，可独立构建和测试；
- 能够稳定运行在公司 VPN 访问边界内。

## 候选方案

### 方案 A：React＋TypeScript 与 Java＋Spring Boot

类型化单页 WEB 前端与 Java 服务端分层，服务端负责业务事务、鉴权、审计、任务和文件授权。适合当前 WEB 产品形态，并与 Java 团队能力匹配。

### 方案 B：服务端页面为主

部署简单，但复杂交互、响应式表格和持续演进的前端体验会使页面与服务端业务逻辑耦合加深。

### 方案 C：其他前端或后端框架

在出现团队成熟能力、公司平台要求或明显成本优势前不作为 P1 默认。框架替换会影响组件、构建、测试和招聘，须通过新 ADR 说明依据。

## 验证证据

- 产品已确认桌面 WEB 为主、移动响应式为辅，不建设原生 APP；
- 团队更熟悉 Java；
- 当前不存在强制复用或禁止使用的公司技术平台。

## 决策

- 前端采用 React＋TypeScript，首期使用类型化单页 WEB 架构；
- 后端采用 Java 21 与 Spring Boot 3.x；
- 前后端通过受版本管理的 HTTP API 协作；功能接口在对应 SPEC 中定义，跨功能错误与接口规范进入共享设计；
- 首期不采用 SSR、原生 APP 或把业务规则复制到前端；
- UI 组件库、构建工具的精确版本、API 文档工具和前端测试工具在工程初始化时选择受支持版本并记录依赖清单。

工程初始化后的现行前端组件决策由 [ADR-012：Ant Design v6 默认组件体系与项目视觉层](./ADR-012-ant-design-v6-component-system.md)承接；被替代的 ADR-011 保留第一轮验证历史，不改写本 ADR 当时有意保留的边界。

## 后果

### 正向后果

- Java 负责复杂权限、事务、审计和后台任务，可复用团队现有能力；
- React 适合项目空间、看板、筛选、表格和上传等复杂 WEB 交互；
- 前后端构建与测试边界清楚。

### 负向后果与控制

- 需要维护两套构建链：工程规范应统一版本、依赖扫描和发布制品；
- API 变化可能引入前后端不兼容：接口必须带契约测试或集成测试；
- 前端组件库若过早锁死会增加迁移成本：仅在工程初始化时选择，不在本 ADR 中预设厂商或主题方案。

## 迁移与回退

所有业务接口保持服务端主导和显式版本控制。前端框架替换不应改变领域模型、权限语义或数据库事实；后端框架替换必须通过新 ADR 给出迁移与回退计划。

## 复审触发条件

- 团队能力或公司平台出现明确、持续的变化；
- 前端运行环境、终端兼容或离线要求改变；
- 当前框架无法满足经验证的安全、性能或维护要求。
