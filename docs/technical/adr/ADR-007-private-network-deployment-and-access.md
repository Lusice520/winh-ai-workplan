# ADR-007：P1 私有部署、VPN 与外网分享访问边界

> 状态：已接受  
> 日期：2026-08-26  
> 决策人：项目负责人  
> 关联需求：PRD V0.4 的员工账号、项目空间、文件分享、审计和外部无账号访问边界  
> 关联验证：VPN 访问控制、网络分区、TLS、主入口不可公网访问、文件分享最小路由、限流、日志和应急失效验证

## 背景与问题

系统部署在公司私有环境，员工可在外网办公但应先经公司 VPN 访问。与此同时，PRD 要求文件可以通过外网链接＋密码分享给无系统账号的外部人员。若直接把主应用开放到公网，会扩大员工账号、项目空间和内部接口的攻击面。

## 决策驱动因素

- 员工业务入口必须只对公司网络和 VPN 可达；
- 文件分享需要外部访问但必须最小暴露；
- 数据库、对象存储、管理接口和后台 Worker 不应有公网入口；
- 网络、证书、网关和日志应能由 IT/安全运营。

## 候选方案

### 方案 A：私有部署＋VPN 主入口＋隔离外网分享入口

员工主系统只经内网/VPN 访问；若启用文件外网分享，则通过独立域名或网关路由到受限分享处理，不暴露主登录和项目 API。

### 方案 B：主系统直接公网开放

可以减少 VPN 使用摩擦，但会把员工账户、管理界面和业务 API 暴露在公网，与当前安全边界不匹配。

### 方案 C：完全不提供外网分享

安全面最小，但与已确认的文件分享产品需求冲突；只有在 IT/安全不能批准隔离入口时才作为延后功能的备选。

## 验证证据

- 已确认系统部署在公司内网或私有环境；
- 已确认员工从外网访问时先走 VPN；
- PRD 已确认外部人员不拥有系统账号，但允许文件级链接＋密码分享。

## 决策

- P1 主应用、管理员入口、业务 API、PostgreSQL、对象存储和 Worker 部署在公司私有网络，不配置公网直连；
- 员工浏览器从外网办公时必须先接入公司 VPN，再通过内部域名和 TLS 访问系统；
- 生产应用采用容器化部署；开发、测试/验收和生产环境逻辑隔离；
- 若启用文件外网分享，使用独立公网域名或独立网关路由，仅暴露受限的分享访问处理；该入口必须具备 TLS、WAF 或等效限流、最小响应、访问日志、撤销和紧急全局失效能力；
- 分享入口不得代理员工登录、管理员操作、项目空间浏览或任意内部 API；数据库和对象存储不因分享需求开放公网；
- IT/安全必须确认实际主机或虚机、网络区、VPN 路由、域名、证书、反向代理、分享入口和备份位置后才能上线；
- 若隔离公网入口不能获批，文件外网分享应延后或关闭，不能以公网开放主系统替代。

## 后果

### 正向后果

- 员工主系统攻击面受 VPN 与私有网络限制；
- 外网分享的暴露范围可独立审计、限流和紧急关闭；
- 部署形态与当前用户规模和运维能力匹配。

### 负向后果与控制

- 员工需要可用 VPN：IT 应提供访问支持和故障处理流程；
- 外网分享仍然需要公网安全能力，不能仅依赖链接密码；
- 实际网络资源与证书审批可能影响上线排期，应作为显式交付依赖跟踪。

## 迁移与回退

未来如需零信任接入、统一身份或公网员工访问，必须新建 ADR，说明身份强度、设备策略、WAF、会话、审计和回退方案。关闭外网分享时，应全局失效分享记录而不影响内部文件和业务事实。

## 复审触发条件

- 公司 VPN、网络区划或零信任平台发生变化；
- IT/安全不能提供隔离分享入口；
- 业务要求员工无需 VPN 的公网访问；
- 容量、可用性或灾备目标要求改变部署拓扑。
