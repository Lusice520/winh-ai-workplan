# ADR-005：P1 自建员工账号、认证与会话

> 状态：已接受  
> 日期：2026-08-26  
> 决策人：项目负责人  
> 关联需求：PRD V0.4 的组织用户、账号生命周期、系统/项目/阶段角色、临时授权、文件权限和审计要求  
> 关联验证：登录、锁定、停用、会话撤销、权限撤回、管理员审计和敏感操作复核

## 背景与问题

公司当前不要求复用统一身份系统，员工主系统访问经公司 VPN。P1 需要自行管理员工账号、组织、角色、项目成员和历史责任，同时确保账号停用后立即不能登录或新增操作。

## 决策驱动因素

- P1 不应被外部身份接口和交付排期阻塞；
- 账号状态、角色、项目权限和审计需要在同一系统中可解释；
- VPN 降低员工访问面，但不能替代应用层认证、授权和会话撤销；
- 后续接入统一身份时不能重写业务权限模型。

## 候选方案

### 方案 A：系统自建员工账号

系统保存员工账号、状态、组织映射和认证信息；认证后的权限继续由本系统判断。适合当前无既有身份依赖的 P1。

### 方案 B：首期强制接入外部统一身份

能集中管理员工身份，但当前没有确定身份源、接口或测试环境，会使 P1 交付受外部条件阻塞。

### 方案 C：不做账号生命周期，只用共享账号或 VPN 身份

无法满足个人审计、离职禁用、项目角色和最小权限要求，不采用。

## 验证证据

- 已确认使用本系统自建账号；
- 已确认员工经 VPN 访问；
- PRD 明确要求账号启停、锁定、调动、离职、历史责任和权限审计。

## 决策

- P1 采用系统自建的员工账号；不开放员工自助注册，也不为外部人员创建项目空间账号；
- 应用使用受维护的密码单向哈希、登录限流/锁定、服务端会话撤销和关键安全事件审计；
- 账号停用、锁定或离职后，服务端立即拒绝新登录和新增操作，并撤销有效会话；历史责任和审计保留；
- 认证只确认员工身份，系统、组织、项目、阶段、字段和文件动作权限仍由统一权限决策模块判断；
- MFA、密码复杂度、会话时长、设备策略、应急管理员和漏洞响应是上线前安全基线，不把未确认策略伪装为当前事实；
- 通过身份 Adapter 隔离未来 OIDC、LDAP 或 SAML 接入；外部身份只能替换认证来源，不能绕过系统权限与审计。

## 后果

### 正向后果

- P1 不受外部身份系统排期影响；
- 可完整实现账号状态、责任和审计；
- 后续统一身份接入不会迫使重建业务角色模型。

### 负向后果与控制

- 系统承担密码、会话和管理员安全责任：`SPEC-IAM-01` 必须完成认证安全设计，并在上线前完成安全验证；
- 初期需由管理员维护账号或导入人员：SPEC-IAM-01 要明确来源、唯一性、调动和离职流程；
- VPN 不是对外分享的替代：外网文件分享保持独立边界。

## 迁移与回退

未来接入统一身份时，为账号保存外部主体映射和认证来源，不改写内部用户标识、责任、权限和审计记录。身份 Adapter 失败时的登录降级策略须经安全评审，不能默认为绕过认证。

## 复审触发条件

- 公司上线统一身份、目录或强制 MFA 平台；
- 安全制度要求改变密码、会话或设备策略；
- 员工外网访问从 VPN 变为其他零信任或公网模式。
