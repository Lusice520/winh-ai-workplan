# 首批业务跨模块契约

> 状态：WI-008 / WI-009 / WI-010 / WI-011 本地实施基线；2026-09-13；负责人 Lusice / Codex  
> 来源：PRD CM/OM/PW/PS/RR/CT/DOC/HG/DG2/TM/ST/MS/CL/WP/PL/BG；ADR-001、003、004、005、006、012。

## 边界与身份

CRM Module 管客户、联系人、商机、行动和业务结果；Project Module 管空间、成员与协作上下文；Presales Module 管投入立项、规定动作、成果版本和报价评审；Requirement Module 管需求、评估、处理关系与验证；Contracts 管签署后事实、节点历史与归档；Files 管私有二进制及版本；Handover 管 DG-01、先行投入授权和对应承诺/实际台账；Delivery 管配置、DG-02、交付基线与后续范围/责任；Work 管原工作记录和执行验证。后续完整执行及财务通过公开接口接续。跨模块不得读取对方 Repository；聚合接口只调用公开摘要。状态变化的强一致同步采用同一事务内的接口/事件，不依赖异步消息决定是否只读。

业务接口沿用 `SessionPrincipal` 和 `AuthorizationService.decide`。`ResourceContext` 中账号/组织来自持久业务负责人，项目与参与关系来自 ProjectDirectory，绝不信任请求提供的 `participatingProject`。列表先过滤权限再计数和分页；不存在和不可见记录统一 404。创建时验证负责人、客户和项目范围；角色/权限撤销下一次请求立即生效。

## 授权

- CRM 权限：`CRM_CUSTOMER_READ/CREATE/EDIT/MERGE`、`CRM_CONTACT_READ/EDIT`、`CRM_OPPORTUNITY_READ/CREATE/EDIT/RESULT`。
- 项目权限：`PROJECT_READ/CREATE/EDIT/MEMBER_MANAGE`；售前权限：`PRESALES_READ/EDIT/REVIEW`；需求权限：`REQUIREMENT_READ/CREATE/EDIT/VERIFY`。
- 售前投入摘要与明细分离：`PRESALES_INVESTMENT_READ/EDIT` 单独授权；无明细权限的响应不包含逐笔用途、金额或依据，写入审计只记录动作类型。
- 各菜单另注册 `NAV_*_VIEW`；导航授权不代替动作权限。成员候选只返回 ID、姓名、组织，不返回手机号/邮箱/账号安全字段。
- 系统业务角色限定公司/组织数据范围；项目角色分配由 IAM 保存项目范围，Project Module 管实际职责与成员生命周期。中央 `decide` 合并有效系统和项目角色，项目角色不能越过分配项目。
- 本地首个管理员通过显式持久业务管理员角色获得新业务配置能力；不向其他现有账号自动授权。迁移记录此授权来源，后续可以在正式角色授权页撤回；所有业务状态和独立验证约束仍适用。
- 公司审批阈值未提供，不自动批准任何投入或报价。具备 `PRESALES_REVIEW` 的另一名启用成员显式复核。本地角色配置可供试点；不得称为已确认公司审批制度。
- 合同摘要与 `CONTRACT_SENSITIVE_READ` 分离；节点及更正历史属于敏感内容。资料 `FILE_READ/UPLOAD/PUBLISH/DOWNLOAD` 和 `FILE_CONTRACT_READ/FILE_COST_READ` 分离。归档提交人不能接收自己的归档，上传人不能发布自己的版本。
- `HANDOVER_READ/EDIT/REVIEW`、`EARLY_START_READ/EDIT/REVIEW`、`EARLY_LEDGER_READ/EDIT` 独立授权；先行投入范围与限额摘要可见不隐含明细可见。新协调/审批角色按参与项目范围，必须实际加入项目。审批、风险及未完成承诺负责人离组前须处理责任，防止孤儿记录。
- `DG2_READ/EDIT/SUBMIT/REVIEW/APPROVE`、`DG2_RESOURCE_COMMIT`、`DELIVERY_BUDGET_READ/EDIT` 与交付配置读/模板维护/规则维护/规则发布独立授权；实际项目经理、资源指定人和独立验证人仍需匹配业务责任。公司最终批准权限不因系统管理员身份、配置选人或模板发布而产生，继续遵守 IAM 委派上限。

## HTTP、并发与审计

- JSON；UUID 稳定标识；日期 `YYYY-MM-DD`、时间 ISO-8601；中文为显示标签，枚举英文为提交值；金额精确十进制且标币种 CNY，人时与费用分开。
- 目录 GET 使用 `q`、`status`、`projectId`、`page`（从 1 开始）、`pageSize`（10/20/50）并返回 `items,total,page,pageSize`；查询、关联和摘要不能泄露无权对象。
- POST 新建提供客户端随机 UUID `requestId`，同一账号/动作/请求 ID 绑定请求摘要并返回相同对象；不同负载返回 409。实体唯一约束为并发最终防线。
- 修改请求携带 `version`，版本过时返回 409 `VERSION_CONFLICT`，不静默覆盖；状态动作、关联、成员变更和评审都纳入聚合版本。服务端事务内重新校验当前状态。
- 400 字段错误、401 会话过期、403 动作拒绝、404 不可见、409 状态/唯一性/版本冲突、413 文件超限。错误沿用 `ApiProblem`，不返回 SQL、堆栈或敏感内容。
- 核心数据、不可变业务历史和审计在同一事务保存。完成、关闭、重开、合并、评审记录操作者、时间、原因和前后状态；不将联系人电话或密码写入审计摘要。
- 取消不写库；提交中禁用重复操作；失败保留表单；成功使关联查询失效。UI 以服务端 `allowedActions` 引导操作，安全仍由服务端执行。
- 聚合页面使用的只读 Directory 校验可能把预期 DomainException 转为缺项提示。这类无写入的参与事务方法声明 `noRollbackFor=DomainException`，避免捕获后外层事务仍被标记回滚而返回 500。写入事务不使用此豁免，任何失败仍整笔回滚。受限源不得返回其正文、金额、文件对象键或内部凭据。
- 合同节点最新表与不可变前后快照分离；归档接收中冻结节点写入。完成事实纠正不变更合同商务状态；约定更正需签署依据并重新归档。所有节点变化仍不生成财务实际。

## 文件、移交与先行投入

二进制经私有 S3 适配器受控传输，单文件默认上限 20 MiB，实际实现为有界字节传输。版本 SHA-256、大小和状态落 PostgreSQL；对象键不对前端暴露。存储不可用返回 503 并避免提交虚假元数据；生产存储、扫描、备份和外部分享另行验收。

DG-01 按版本化类型模板生成清单，不在 GET 中创建记录。审批冻结清单、责任人、到期日和有效源；批准时重检，生成不可变移交包。来源合同、文件和售前成果分别通过公开 Directory 校验；新版本/作废/授权变化不静默沿用旧引用。DG-01 通过仅获得交付准入，主阶段仍为 PRESALES，后续 DG-02 才负责交付基线与阶段转换。

提前开工由独立成员批准具体范围、工时/费用上限、期限和停止条件。普通新承诺仅在授权生效期内；占用为实际发生加未核销承诺，部分实际不重复计数。同项目锁串行检查，已发生超限需明确原因并冻结新增普通承诺。停止、过期、收口授权与正常移交转正分别留存，不删除既有台账，也不制造合同归档事实。

## 交付基线、责任交接与范围变更

DG-02 读取当前 DG-01 来源，选择发布配置快照；九组检查核对商务接收、团队资源、阶段、计划、范围、预算、遗留及当前授权。固定类型内容通过严格 DTO 解码，未知字段/关联跨项目均拒绝。准备对象使用稳定 UUID；工作包通过 WorkDirectory 接纳原需求工作记录，保存原 ID 和来源。

提交保存完整不可变快照、哈希和轮次，同时将原工作包标记 IN_REVIEW；指定独立会签、最终批准前重查源版本与当前权限。批准原对象 V1、Work 的 BASELINED 状态与 Project 主阶段 DELIVERY 同事务生效。Work 的 OPEN / PENDING_VERIFICATION / DONE 是执行状态，不能用它替代基线状态；只有实际负责人可提交完成，指定另一人验证，需求仍按原需求流程独立关闭。

| API 族 | 责任与事务 |
|---|---|
| `/api/delivery-configurations` | 配置草稿、发布版本、复制与退役；具体发布/维护权限分离，实例保留原发布快照 |
| `/api/delivery-initiation/{projectId}` | 原项目准备、对象、资源、遗留、轮次、基线和修订；GET 不创建数据 |
| `…/responsibility-transfers` | 全量未结责任预览、原/新人员、显式角色变化、本人接收、指定资源重签、经理统一生效 |
| `…/scope-changes` | 一份未结束整组草案、原版本与候选图、预留 ID、提交/退回/撤回/取消/独立批准、冻结快照与操作说明 |
| `…/objects/{id}/history` | 对象修订前后值与原因；不隐含对象写入权或敏感预算阅读权 |

里程碑/预算由有权经理直接修订后形成有效 Vn；其他单对象变更须独立确认。新增互相关联的范围使用整组草案，逐步维护阶段、里程碑、工作包、清单、主/工作包计划、预算和资源差异。新 ID 只在草案中预留；批准时由受信 `WorkDirectory.approveDeliveryPackage` 在原 ID 建立/接纳 Work，并统一应用对象、资源、预算、策略和完整下一版快照。已有执行中的工作继续运行；触及的原工作包版本、状态或责任已变时阻止覆盖，DONE 不被后续范围重写。停用未执行工作包标记 RETIRED，禁止继续提交完成。

范围草案记录原基线结构摘要和触及的对象/Work 版本；更新引用须经理明确执行，先撤回冲突差异后保留其他草案。每次提交独立保存当轮原内容、候选内容、差异与依据；退回、重提不会覆盖旧快照。操作说明从 V17 开始单独持久留存，与同次业务写入和幂等完成原子提交；不为早期合成记录补造缺失说明。

资源请求和承诺按人员锁串行；日期边界包含首尾日，按实际重叠峰值求和。整组草案合并本提案全部拟安排与其他项目正式投入，同一资源 ID 只计一次；草案签认不提前占正式容量。超容量须先记录冲突再给出影响、协调结论与升级路径；后续新增重叠使原协调哈希失效时重新核对。资源撤回由原指定人确认，交接后的新安排由拟任指定人重签，最终生效前再检查。

责任交接由 Work/Requirement 的公开 `ProjectResponsibilityContributor` 枚举和原位转交未结职责；已完成工作、已关闭需求/遗留保留原负责人。接任角色先经现行 IAM 授予范围校验，原角色最后收回；任何来源、职责、角色或版本变化均拒绝旧交接。成员权限、跨模块责任与资源在同一事务应用，禁止只改姓名或绕过委派上限。

预算行、授权额度、完整规则、财务意见、整组理由/影响/依据及操作说明按预算阅读权投影；单项变更/修订的理由、影响和依据同样不向缺少预算阅读权的账号下发。跨项目资源重叠仅在可读项目中返回 ID 和项目名，否则只返回匿名时间/容量。企业正式重大变更复审阈值仍需试点配置确认，不自动重开原 DG-02。

当前立项页从真实源状态派生检查、责任待办与期限；独立消息中心、主动提醒和完整工作台汇总属于后续统一接续，尚未宣称完成通知平台。

## 原批准对象的执行事实

`ApprovedDeliveryDirectory` 只返回 DG-02 已批准、主阶段 DELIVERY 项目的非财务原对象及当前经理。Execution 管原 Stage/Item/Milestone 下的实际；Work 继续拥有工作包完成状态。新 `DELIVERY_EXECUTION_READ/EDIT/REVIEW/MANAGE` 使用通常的项目授权，并叠加当前实际责任与成员有效性，不产生公司审批权。V18 新增执行状态、清单资料、分批事件、里程碑实际及不可变历史五张表，V1–V17 不改写。

| API（前缀 `/api/projects/{projectId}/execution`） | 语义 |
|---|---|
| `GET /`、`GET /items/{id}`、`GET /history/{objectId}` | 当前非财务范围与实际、某项分批事实、原对象历史；GET 无写入；项目总览含最近 100 条及本人待核验 |
| `POST /stages/{id}/actions` | START/PROGRESS/PAUSE/RESUME/COMPLETE/REOPEN；经理控制状态，负责人报告 0–99，完成检查通过后为 100 |
| `POST /items/{id}/profile` | 经理显式指定到货/安装适用性，品牌型号供应商与原因；有有效事实时不能改环节绕过数量关系 |
| `POST /items/{id}/events` | RECEIVED/INSTALLED 直接记录，ACCEPTED 提交指定独立核验；正数量两位小数，实际日期不晚于今天、不早于阶段开始 |
| `POST /events/{id}/actions` | VERIFY/RETURN/REVERSE；实际指定验证人、处理人与项目归属在命令时核对；冲回保留原事件数量并追加反向关系 |
| `POST /milestones/{id}/submit`、`POST /milestones/{id}/actions` | 关联 Work/清单满足条件后提交；指定他人核验/退回；重开先处理已完成阶段；不产生合同或财务实际 |

每次命令含 requestId、执行 version（首次 -1）及当前批准对象 objectVersion。项目锁将范围变化、数量检查、状态事实、历史和幂等完成串行在同一事务；分批写入与核验都会推进该清单资料版本。有效待验收与需重核的旧验收仍占用数量，按实际日期的累计前缀检查到货/安装/验收关系。重复请求先核对原请求摘要，重放不新增数量。

`BaselineApplied` 在原范围生效事务中检查已有事实，不能停用有实际的对象、缩小到净数量以下或改换清单所属范围；异常回滚整个原生效事务。阶段/里程碑的完成依据摘要包含当前关联清单与工作包的实质内容；来源标准变化显示 NEEDS_REVIEW，旧日期/结论留存，须明确重开或退回后重新核验。仅计划日期/人员变化不改写物理事实。Work 的待完成动作通过当前项目和阶段执行校验，旧 DONE 不补造新阶段开始。

里程碑各轮及清单历史保存原文件版本 ID，查询时逐个通过 FileDirectory 投影可读文件；受限项只返回数量，不返回标题、文件 ID 或对象键。执行历史的前后 JSON 去掉文件 ID，另附授权后的 beforeFiles/afterFiles。待验证职责通过 `ProjectResponsibilityContributor` 参加原项目人员交接；保留提交者和原事件，接任者仍需有效读取/核验权限与独立性。

## 原工作包的任务执行

WI-012 / SPEC-TASK-01 在 Work 模块维护原 TASK 身份与状态，V19 增加同 ID 的任务正文及不可变前后快照；V20 保留 V12 来源规则并增加 DELIVERY_TASK + TASK + 无来源需求，已应用迁移不改。新建无需求时不造来源；接纳同项目 OPEN TASK 保留 ID、创建来源与原需求。原 Work detail 增加可空 taskWorkPackageId，原 transition 拒绝已接纳任务并引导受控任务入口。

GET/POST `/api/projects/{projectId}/work-packages/{id}/tasks` 返回/建立原包任务；GET/PATCH `/api/projects/{projectId}/tasks/{id}` 读取/修订计划；POST 任务 `/commands` 管理本人进展、完成提交、独立验证/退回和经理/包负责人的取消/重开。使用原 WORK_READ/EDIT/REVIEW 与项目参与范围，叠加实际职责；不增加公司审批能力。每次写入持有项目锁并核对 Work/profile 双版本、父范围与幂等摘要。

ExecutionDirectory 只读提供原阶段状态与实际开始；已停用阶段仍返回历史状态，不能因此丢失原任务记录。正式实际须项目 ACTIVE、阶段 IN_PROGRESS，日期不早于原开始且不晚于上海今日，进度整数 0–99；完成报告 100 仍待指定其他人核验。预计人天以 0.5 为单位，与后续实际工时分开。

Work 的 COMPLETE/VERIFY 事件检查未结或需复核子任务；完成所有任务不会自动完成工作包。批准范围变化按原包和选中清单的实质签名派生需复核，原日期/完成事实不覆盖。父包已有完成提交后禁止改变子任务；范围生效事务拒绝停用有未取消任务的包或改换已有实际任务的阶段。任务取消后历史保留、不进入完成率。

文件提交和 VERIFY 使用当前发布/读取校验，历史快照保留原版本并按当前权限分别投影；不直出受限 ID/标题。Work contributor 延续未结任务责任，旧提交人不替换，指定他人核验独立性不放松；交接事件写入同一任务历史。GET 读取不产生业务事实。

Work 的 CompletionEligibility 对需复核的旧 DONE 任务向下游返回 NEEDS_REVIEW，原数据库状态和历史不覆盖，防止需求关闭使用失效成果。

## 本地初始字典

以下为本次授权开发采用的可调整初始值，并非对公司制度的推断：商机等级 A/B/C/D，进展 LEAD（初步接洽）/QUALIFIED（需求明确）/SOLUTION（方案沟通）/QUOTATION（报价投标）/NEGOTIATION（商务谈判）；新商机最小建档后缺行动显示待补齐；30 日无事实更新显示长期无进展，不自动关闭。客户统一标识精确唯一，名称相同/包含只提示，集团子公司不自动合并。对象编号使用前缀与服务端唯一标识，不含客户名称。

项目创建继承原商机与客户引用，要求指定售前负责人（默认可选自己）；初始主阶段 PRESALES、重点 NOT_SET、状态 PENDING_INITIATION、结果 PENDING。项目名称可编辑，结果来自商机唯一事实；在 DG-02 前不允许切换为交付。固定入口保留，尚未交付的子域以清楚的未开放说明呈现。

## 验证与回退

模块集成、HTTP 越权、跨账号验证、并发/重放和 PostgreSQL 迁移共同验证。数据库 V5 起前向新增业务表及权限；旧数据不删除。代码和 Flyway 版本同步发布；关闭新菜单只能停止入口，不能替代权限撤销。未运行的验证必须明确列出。

## 经营预测与实际收入

WI-013 / INC-01 新增 Finance 模块，V21 保存预测册、预测版本、实际收入和不可变前后事件。预测册唯一键是 projectId + YYYY-MM + ISO 币种；复合外键确保当前/草案属于本册，一册最多一个草案。金额 API 输出十进制字符串、数据库 NUMERIC(14,2)，单行最多两位且不舍入；汇总不混币种，客户端以整数分计算版本比较和合计。

GET 项目 `/income-workspace`、预测册及历史、收入详情按当前角色读取；POST `/income-forecasts` 保存草案，预测册 `/commands` 发布/放弃。POST `/incomes`、PATCH `/incomes/{id}` 填报，收入 `/commands` 提交/退回/确认/撤回/取消；整笔冲销建立新的 REVERSAL，原收入保留。每次写入带 requestId 及当前版本，项目锁将来源校验、更新、事件和幂等结果放在同一事务。数据库部分唯一索引保证同一原收入只有一笔已确认冲销；冲销归实际发生月份，旧月份不重写。

ProjectDirectory 和参与范围确认 FINANCE_READ/FORECAST_EDIT/INCOME_SUBMIT/INCOME_CONFIRM；无隐式公司角色授予。指定确认人须有效项目成员、有相应权利、不同于当前提交人。PAUSED 可补录已发生事实，CLOSED 只读。当前 ownerId 与原 createdBy/submittedBy 分开，未结收入通过 ProjectResponsibilityContributor 接入原成员退出检查和 DG-02 正式交接，保持旧轮提交者与独立确认边界。交接读取无 FINANCE_READ 时不暴露收入 related 项的标题/ID。

ContractDirectory.financialReference 返回可读的同项目合同身份/版本和归档状态，不跨模块读取 Repository；新来源/提交/确认要求已归档且签署资料有效。历史来源可保留终止前版本，当前无权时只显示受限提示。FileDirectory 在变更时核对当前发布文件，历史逐项投影旧版本，受限项不输出 ID/标题/对象键。可选合同的签署资料受限不会使整个收入工作台不可读；受限依据不能通过修订被静默丢弃。

资金计划入口兼容原实施预算，仅按读取能力显示经营收入模块。桌面/移动端使用同一受控 API；URL 保留筛选与分页，快速连续筛选合并尚未完成导航的参数；保存冲突保留输入。预测引用收入仅预填来源，不自动生成计划金额、确认收入或发布。会计、现金、发票及成本事实由后续子域分别承担。
