# 售前投入立项单功能需求规格说明书

> SPEC-PS-01 · v0.1 · 2026-09-12 · ready-for-implementation  
> Owner：Lusice；作者：Codex；来源：[PRD](../PRD.md) PS-01、PS-06；[WI-008](../../development-testing/work-items/WI-008-business-delivery.md)。

## 1. 功能概览

商务、售前负责人从同一项目空间申请投入，授权复核人检查依据后批准或退回。SG-01 只控制售前投入，不能替代合同、DG-01 或 DG-02。

## 2. 功能范围与产品设计

提供申请草稿、提交、复核、退回重提、批准额度及期限、已承诺和实际投入流水。使用项目详情右侧评审栏和专门抽屉。人时、费用分别显示；不推断内部费率。已发生投入不可清零，修正以冲正记录保留原事实。审批阈值未提供，当前没有自动简化批准路径。

## 3. 流程说明与流程图

售前负责人填写投入目的、范围、人员、人时、费用、成果、有效期和退出条件。提交后由另一名获授权人员明确复核；退回必须说明缺项，允许修改后再次提交。批准后空间变为进行中，用户在有效范围内登记投入。失败或取消不产生半条批准记录。

```mermaid
flowchart LR
 A[投入申请草稿] --> B[提交 SG-01]
 B --> C{授权人员复核}

 D --> E[承诺与实际投入流水]
 E --> F[期限/额度复核]
```

## 4. 特殊业务规则

1. 提交和批准记录分开；复核人不能为提交人。服务器验证授权、项目状态及版本。
2. 人时/费用非负，批准不得高于本次申请；已承诺加实际不得超批准额度或过期，否则拒绝并要求新一轮投入申请。
3. 追加申请保存新版本，不能覆盖旧批准与实际；未成交关闭项目只读，投入与复盘仍可查。

## 5. 页面与状态说明

状态：DRAFT、SUBMITTED、APPROVED、RETURNED。详情显示申请轮次、申请人/复核人、日期、额度、理由和流水；每个状态仅提供可用操作。加载/错误可独立重试，未立项显示主要动作“申请售前投入”。

## 6. 查询条件

项目、立项状态、责任人；与项目目录同一数据范围。投入按类型 COMMITTED/ACTUAL、日期筛选。

## 7. 列表与状态字段

申请标题、目的、范围、预计人时/费用、批准人时/费用、开始/到期日、预期成果、退出条件、状态、版本、申请及评审时间。投入有日期、类型、人时、费用、说明及创建人。

## 8. 表单字段

目的/范围/成果/退出条件必填，单项最多 2000 字；人时/费用最多两位小数；截止日期不早于开始日期。申请金额是 CNY。复核需结论及意见；退回必须填写原因。流水说明必填。

## 9. 交互、提示与异常

未批准、过期、超额度、项目已关闭、重复提交和版本冲突均由服务端拒绝且说明原因。关闭有改动的抽屉前确认放弃；保存失败保留填写。单个审批只成功一次，网络重试返回原结果或明确最新状态。

## 10. 数据、权限与边界

Presales Module 保存申请轮次、投入流水；Project Module 提供项目上下文并在通过后切换立项状态；CRM 提供原商机。`PRESALES_READ/EDIT/REVIEW` 分开。项目参与人可按售前查看授权读取工时、费用总额及批准额度摘要；逐笔投入、用途和依据还需 `PRESALES_INVESTMENT_READ`，登记与冲销同时需要 `PRESALES_INVESTMENT_EDIT`。无明细授权时接口返回 `investmentDetailsVisible=false` 和空明细数组，摘要数值不受影响。默认项目负责人/协作人/评审人角色不自动获得明细授权，需明确配置。

## 11. 功能详细设计

遵守 [业务共享契约](../../technical/designs/shared/BUSINESS_DELIVERY_CONTRACT.md)。`GET /api/projects/{id}/presales` 返回申请历史、最新轮次、投入和 allowedActions；`POST /initiations` 新建申请，`POST /initiations/{id}/submit`，`POST /initiations/{id}/review` 显式提交/复核；`POST /investments` 登记投入。后端使用独立 `presales_initiation` 与 `presales_investment` 表、UUID 项目引用、版本和 FK。审核与项目状态同一事务；流水登记锁定项目/批准申请再计算额度。新建按 requestId 幂等，审计不含敏感文件内容。默认字典仅作为本地实施初始值，公司制度上线前配置。

## 12. 测试设计与验收标准

覆盖申请 → 提交 → 他人批准 → 投入持久化；退回重提；自身审核拒绝；未批准、超额、过期、负数拒绝；重复/并发不双记账；关闭项目只读；刷新后历史仍可查；桌面与 390px 真实操作。

## 13. 待确认问题

公司级分级审批阈值与复核岗位映射待试点确认，不阻塞显式人工审批链的本地实现；不虚构自动批准。
