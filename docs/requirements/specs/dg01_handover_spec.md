# DG-01 交付移交单功能需求规格说明书

> SPEC-HG-01 · v0.1 · 2026-09-12 · ready-for-implementation  
> Owner：Lusice；实施：当前 Codex；来源 PRD-HG-01～03、CT-02、DOC-06，WI-009。

## 1. 功能概览

责任商务/售前在原项目形成可接收的移交清单，由拟任项目经理或指定接收人独立评审。通过后生成不可变移交包，主阶段仍为售前，为 DG-02 提供当前有效依据。

## 2. 范围与页面

项目空间“交付移交”包含 DG-01 清单、缺项责任、商务依据、评审轮次与移交包。紧凑事实栏显示齐备率、必需缺项、评审状态和接收人；主栏分组清单，侧栏显示准入链路与最新评审。另设“提前开工”页签，遵循 HG-02。

## 3. 流程

选择初始项目类型、接收人和补齐期限 → 快照清单 → 配置适用性、责任与版本引用 → 系统检查缺项 → 提交 → 接收人独立通过或退回 → 保留当轮快照并生成移交包。退回重提保留旧轮次。通过后需修改时显式重开下一轮并填写原因，旧包永久保留，当前准备状态停止供 DG-02 使用。

## 4. 业务规则

初始类型为系统集成、技术服务、设备供货，是本地实施可配置起点，不宣称已经确认公司分类。模板版本 `HG-2026-09-v1` 固定记录在对象中。共同覆盖项目基础、商务依据、范围与技术、验收与计划、投入与风险；设备清单在设备供货/系统集成时条件必需，联调交底在系统集成时条件必需。其余条件项不适用仍须说明。后续规则发布不改写已初始化项目。

共同必需项不能由普通编辑直接改为不适用或手工勾选完成。项目基础自动引用原项目；商务依据可选择已归档有效主合同、当前发布的中标通知/委托函、有效提前开工审批；中标通知和委托函不伪造为合同。其他成果引用同项目当前发布资料或当前已批准售前成果。说明文字用于解释，不能替代要求的正式版本。条件项不适用理由和可选项缺项保留在移交包中，由本轮接收人一起核验。

所有适用必需项必须有启用项目成员负责人和期限，当前版本及状态齐备。已关闭项目不能提交；商机负面结果关闭原空间后不可绕过。提交/通过都重新检查，不信任前端完成数。接收人不能是提交人；通过者必须是指定接收人且有 DG-01 评审权限。模板、人员、清单、业务依据或引用版本改变使提交快照过期，须退回重提。

## 5. 状态

DRAFT、SUBMITTED、RETURNED、APPROVED；缺项为 MISSING/INVALID/READY/NOT_APPLICABLE/OPTIONAL。DG-01 通过不改业务结果、不替代合同归档、不修改项目主阶段。移交包因源资料替代、作废或新轮次而不再当前有效时保留历史，同时阻断后续 DG-02 使用。

## 6. 查询

项目内查看；按分组、是否必需和缺项筛选。清单内容遵循 HANDOVER_READ；关联合同与文件仍执行各自密级权限，无权时显示受控依据，不返回标题、金额、对象键或正文。

## 7. 展示字段

类型、模板版本、状态、接收人、计划移交日期、清单项名称/分组/适用性/负责人/期限/有效性/缺项原因/引用版本；历史轮次、提交者、接收者、意见、时间、移交包编号和当前有效性。

## 8. 表单

初始化：类型、接收人、期限。清单编辑：负责人、期限、文件/成果版本、说明、条件项适用或不适用原因。商务依据：CONTRACT/AWARD/ENTRUSTMENT/EARLY_START 及对应记录。提交与评审：明确说明；退回、重开必填原因。

## 9. 异常

缺项阻断提交并列明责任；版本过期 409 且保留表单；未授权、跨项目、失效文件与自审由服务端拒绝。当前资料虽可查看但非当前发布状态，不能作为合格依据。项目成员移出前须交接未完成移交责任。

## 10. 数据与权限

Handover 独占 handover_case、handover_item、handover_review、handover_package；独立 HANDOVER_READ/EDIT/REVIEW。接收包包含审核时的清单、源引用、责任、意见与校验摘要，历史不可覆盖；返回包内容仍按当前资料权限裁剪。

## 11. 功能详细设计

`/api/projects/{id}/handover` GET/POST 初始化；`/items/{itemId}` PATCH；`/basis` POST；`/submissions` POST；`/reviews/{reviewId}` POST；`/reopen` POST；`/packages/{packageId}` GET。请求携 requestId/version。项目写锁串行命令，源模块通过 FileDirectory、ContractDirectory、PresalesDirectory、EarlyStartDirectory 检查，禁止跨模块直接读表。快照按稳定顺序序列化并存 SHA-256；批准时重算对照；获批包沿同项目引用供 P2 接续。

## 12. 验收

普通与条件必需缺项、当前版本变化、跨项目、自审/非接收人、返回重提、重放、并发、不可变包、源失效、主阶段不变化、普通权限不泄露合同/成本明细、390px 页面不溢出。

## 13. 待确认

公司正式类型和各专业清单、接收岗位与授权规则在真实试点配置；不得把本地通用模板作为公司制度。DG-02 的团队和基线由下一独立 SPEC 接续。

## 14. 变更

v0.1：当前有效成果、可追责缺项、独立评审及移交包，2026-09-12。
