# 项目团队与资源承诺（SPEC-TM-01）

> 版本：v0.2；Owner：Lusice；作者：Codex；2026-09-13  
> PRD：4.13；状态：ready-for-implementation；WI-010。

## 1. 功能概览

P0；项目经理、技术负责人、工作包负责人、资源部门责任人与 PMO。入口为原项目“成员”及交付立项“团队与资源”。

## 2. 功能列表

团队责任、资源申请、部门承诺、容量重叠检查、明确冲突协调、承诺变更、责任交接。采用实际项目成员与单独责任事实；不把角色名当作人事任命，也不让选审批人自动授予审批权。

## 3. 流程说明与流程图

项目经理将启用人员加入原项目并配置可下放的项目角色，指定关键责任后按工作包提出人员、日期和投入需求。指定资源责任人依据本部门范围查看重叠申请，确认可用容量或记录冲突。冲突经明确协调处理后才能满足准入；原请求和所有签认保留。

```mermaid
flowchart LR
 A[加入原项目并落实责任] --> B[工作包资源申请]
 B --> C[指定部门责任人核验]
 C -->|容量满足| D[承诺]
 C -->|重叠冲突| E[冲突记录与协调]
 E -->|明确结论| D
 D --> F[DG-02 团队快照]
 F --> G[后续换任交接与权限调整]
```

退回/撤回不删除资源签认，但修改人选、日期或投入后原承诺失效，必须重新确认。批准后交接保留原批准责任快照，不重跑 DG-02。

## 4. 特殊业务

启用账号且实际参与项目；项目经理、技术负责人和每个适用工作包负责人必填。资源负责人不能替他人伪造承诺，需指定人、部门授权和有效权限。跨项目按同一人员和日期重叠检查每日请求投入；可用容量由有权部门签认，不凭系统默认工时推定公司制度。超容量必须显式冲突结论、影响和升级，不能静默放行。并发用人员锁串行。非可见项目只给冲突数量与必要日期/投入，不泄露名称正文。

## 5. 页面 / 状态说明

资源 REQUESTED/COMMITTED/CONFLICT/RESOLVED/REVOKED；显示承诺人、时间、版本、重叠和结论。评审期引用内容冻结；后续撤销和换任须按责任交接处理，保留历史。

## 6. 查询条件

工作包、人员、申请状态、日期范围；成员候选只显示姓名/组织和 ID。

## 7. 列表字段 / 状态字段

角色、人员、所属组织、工作包、起止日、每日需求、部门可用容量、承诺状态、冲突数量、责任人与签认时间。

## 8. 表单字段

资源：工作包 ID、人员 ID、指定承诺人 ID、起止日、每日工时（正数、两位小数、不超过 24）、需求说明；签认：可用每日容量（0–24）、同意/冲突/解决、依据与影响、升级路径。交接：原/新责任人、未结事项映射、交接依据、生效时间、权限回收和授予的显式清单。

## 9. 交互说明

资源待办直接打开原申请；确认前显示当前跨项目重叠。修改需求提示原承诺将失效。提交后刷新准入状态，不提前显示已承诺。

批准后换任在同一项目一次交接一对原/新人员。项目经理预览项目经理、技术负责人、适用阶段、里程碑、未完成工作包、未结需求/任务/问题/变更、未结遗留及尚未到期资源的全部受影响职责，说明依据后发起。新责任人确认接收，变更资源再由各请求指定的承诺人重新签认，项目经理最后确认。生效时间记录最后确认成功的服务端时间，当前版本不支持预约生效。

接收、签认和最终确认都重新核对版本与新增未结项；变化后须撤销旧交接并重新发起。新责任人须已是有效成员；角色调整逐项展示原角色、拟保留/增加/回收角色，沿用当前管理者下放上限。职责、资源和角色在同一事务中生效，任一失败均不部分转移。销售/售前原责任和配置规则中的公司审批授权不由交付换任自动转移；不能据此移除仍担任其他必要职责的成员。

已完成工作与已关闭需求、遗留保留历史责任；当前职责更新不覆盖批准快照。尚在验收中的结果保留原证据提交人，新验证人不能是现任负责人、证据提交者或需求历史处理者。交接历史保留接收、资源签认和最终生效时间。

## 10. 提示说明

“关键资源尚未承诺。”“资源需求已变更，请重新确认。”“存在重叠容量冲突，请记录协调结论。”“该成员仍有未结责任，请先完成交接。”

## 11. 异常处理

越权/跨项目/停用人员拒绝；版本冲突 409；并发重叠重新计算；移除未结负责人或评审人阻断。失败保留表单。

## 12. 数据记录

成员和 IAM 项目角色仍由原模块保存；交付模块保存实际责任、资源申请及签认历史、冲突与交接。当前有效责任和批准快照分开，不覆盖历史。

## 13. 权限与边界

成员变更沿用 PROJECT_MEMBER_MANAGE 与下放上限；团队草案叠加 DG2_EDIT 和项目经理责任。DG2_RESOURCE_COMMIT 叠加指定承诺人与人员组织范围；不能因部门角色改写项目预算或计划。系统管理员不自动获得资源或公司批准权。

## 14. 验收标准

真实多账号申请/承诺/冲突/协调，需求修改使承诺失效；两项目同一人员并发不漏检；部门与项目隔离；关键角色缺失阻断；冻结、换任、旧责任快照与权限即时撤销可验证。

## 15. 待确认问题

公司部门授权、资源可用容量和升级人员由实际配置与签认提供。
