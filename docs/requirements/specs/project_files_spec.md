# 项目资料与文件版本单功能需求规格说明书

> SPEC-DOC-01 · v0.1 · 2026-09-12 · ready-for-implementation  
> Owner：Lusice；来源：PRD-DOC-01～03、CT-03/04，ADR-004、WI-009。

## 1. 概览

统一管理项目资料的真实二进制、元数据、版本和业务关联，为售前成果、合同及移交提供受控文件依据。

## 2. 范围与设计

项目资料列表与版本抽屉，上传/修订、提交评审、独立发布或退回、作废、受控下载。按项目、阶段、资料类型、密级、状态和关键词查找。首批使用应用受控传输，文件大小有界，不向浏览器暴露存储路径或密钥。外网分享、NAS、预览转换、病毒扫描另立后续实现，页面不虚构这些能力。

## 3. 流程

选择实际文件上传为草稿 → 提交评审 → 另一授权成员发布/退回 → 业务对象关联有效版本。新版本草稿不使旧发布版失效；新版本发布时原发布版转为已替代。作废必须原因，保留二进制和历史。

## 4. 规则

版本不可覆盖，SHA-256 保存并在读取时核对；大小上限由运行配置控制，首批默认 20MiB，不声称满足生产容量。禁止空文件、路径型文件名、控制字符；显示原名，但对象键独立生成。所有下载以 attachment 和 nosniff 返回，避免用户内容在主站执行；不提供任意 URL 抓取。错误详情不返回对象存储凭据或路径。

## 5. 状态

DRAFT、IN_REVIEW、PUBLISHED、RETURNED、SUPERSEDED、VOID。资料密级 INTERNAL、CONTRACT、COST。合同/成本还需对应独立读权限；文件查看、上传、发布、下载分别判断。失去当前项目权限后历史版本也不可访问。

## 6. 查询

项目、主阶段、资料类型、状态、密级、关键词。只返回权限范围内的元数据，先过滤再分页，不通过计数泄露敏感资料。

## 7. 字段

标题、资料类型、主阶段、密级、当前有效版本、最新版本及状态、上传人、更新时间、大小。版本抽屉显示变更原因、校验值、评审人和意见。

## 8. 表单

上传/修订需要真实文件、标题/类型、密级和版本说明。修订不得降低密级；首批密级如需调整，另行受控申请，不默默放宽权限。评审和作废均必填说明。

## 9. 异常

上传失败保留表单与文件选择，重试 requestId 和文件校验相同则复用结果；同键不同内容拒绝。存储不可用返回可理解的服务暂不可用，不能产生可下载但没有二进制的记录。数据库回滚时允许孤儿二进制留待后台对账，禁止删除已引用文件来伪装回滚成功。

## 10. 数据与边界

Files 模块独占 project_document 和 document_version；二进制通过 ObjectStorage Adapter 保存到私有 S3，元数据在 PostgreSQL。FileDirectory 提供资料授权摘要、有效性校验和受控下载。业务模块只存版本 ID。配置为端点/桶/区域/凭证环境变量，不写入仓库。

## 11. 功能详细设计

`GET /api/projects/{id}/files`、`POST /api/projects/{id}/files` multipart(file, metadata JSON)，`GET /api/files/{id}`、`POST /api/files/{id}/versions`，`POST /api/files/{id}/versions/{versionId}/transition`，`GET /api/files/{id}/versions/{versionId}/download`。JSON 元数据携 requestId、version（修订）、title、kind、classification、changeNote。写入先检查项目权限并锁项目，再算校验并预留幂等记录，上传成功后保存元数据。发布独立于上传；发布者不能等于本版上传人。记录浏览/下载与每次状态变化审计。默认无 S3 凭证时文件上传/下载明确不可用，其他模块继续工作。

## 12. 验收

上传后下载校验一致；重新启动仍读到同一内容；修订草稿不替代有效版；自发自审拒绝；新版本发布后旧版可追溯；作废立即影响后续业务有效性；无下载权不能读二进制；无合同/成本权限不见其元数据；关闭/跨项目/冲突/重试/存储错误受控。

## 13. 待确认

生产存储产品、许可证、安全扫描、文件规模和备份按 ADR-004 实施前/上线前要求分别验收。本地 S3 协议验证服务只用于开发。

## 14. 变更
