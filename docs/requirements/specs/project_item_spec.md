# 项目清单（SPEC-CL-01）

> P3 接续：原对象的实际执行、独立验收、冲回/重开与执行职责交接见 [SPEC-EXEC-01](project_execution_spec.md)，本文件继续定义批准基线。

> 版本：v0.1；Owner：Lusice；作者：Codex；2026-09-13  
> PRD：4.13；状态：ready-for-implementation；WI-010。

## 1. 功能概览

P0；原项目固定“项目清单”入口，承载设备、物料与交付项的范围，P3 在同一 ID 追加执行。

## 2. 功能列表

清单建档、分组、规格数量、工作包/里程碑/阶段关联、采购需求、验收范围与后续受控版本。采用统一清单，不新增交付单元，不用空清单绕过评审。

## 3. 流程说明与流程图

责任人依据接收范围登记已知交付项，关联承担它的工作包与验收节点，说明是否需采购。预检核对非空、引用和预算覆盖；批准后原 ID 接续采购、到货、安装和验收，范围变化先经授权确认发布新版本。

```mermaid
flowchart LR
 A[已知范围登记] --> B[阶段工作包里程碑与采购需求]
 B --> C[完整性与预算映射校验]
 C --> D[DG-02 原清单 V1]
 D --> E[原项接续执行或范围修订]
```

草案移除为留痕停用，引用未解除时提示缺项；评审和 V1 不删除历史。

## 4. 特殊业务

数量必须正数，最多两位小数，单位必填。关键采购需映射预算；无采购需求保留显式否定。每项关联同项目适用阶段、工作包及验收里程碑。跨对象先渐进保存草案，但提交时不能缺关联。只有后续细化且不影响当前批准范围的缺项才可作为非阻断遗留。

## 5. 页面 / 状态说明

草案/冻结/批准/有效修订；表格显示采购需求和验收关系。采购/到货/安装/验收尚无事实时显示“尚未发生”，不推算完成。

## 6. 查询条件

名称、类别、工作包、阶段、采购需求、版本。

## 7. 列表字段 / 状态字段

名称、类别、规格、数量/单位、阶段、工作包、验收节点、采购标记、当前版本。

## 8. 表单字段

title（160）、category（EQUIPMENT/MATERIAL/DELIVERABLE）、specification（2000）、quantity、unit（24）、acceptanceScope（4000）、stageId、workPackageId、milestoneId、procurementNeeded、procurementNote（2000）。更新版本/原因；批准后范围提案增加影响和依据及独立确认人。

## 9. 交互说明

筛选表格→抽屉维护→关联原对象；保存立即重算缺项。长规格展开，不挤占主要名称和责任；窄屏横向表格可操作。

## 10. 提示说明

“请至少登记当前已知交付项。”“此清单项缺少验收关系。”“采购需求尚未映射预算。”

## 11. 异常处理

数量/跨项目/失效引用拒绝；冻结与版本冲突 409；停用有关联对象不悄悄删除关系。

## 12. 数据记录

清单稳定 ID、类型正文与版本、停用标志、引用关系、V1 和后续修订快照；执行事实由后续模块引用原 ID。

## 13. 权限与边界

DG2_READ；DG2_EDIT 叠加项目经理/负责工作包范围。批准后实质范围修订独立授权确认；不得直接切阶段或登记财务实际。

## 14. 验收标准

非空范围、数量/单位、采购与预算映射、关联和跨项目校验；冻结、同 ID 批准、停用可追溯；未经确认不改变批准范围。

## 15. 待确认问题

公司采购清单标准库仍属后续候选，本功能不伪造标准库。
