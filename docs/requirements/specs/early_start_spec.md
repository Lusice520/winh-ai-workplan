# 提前开工与最小承诺台账单功能需求规格说明书

> SPEC-HG-02 · v0.1 · 2026-09-12 · ready-for-implementation  
> Owner：Lusice；实施：当前 Codex；来源 PRD-HG-04/05、WI-009。

## 1. 功能概览

在商务依据尚未完全具备时，保存经独立批准的有限开工范围，并控制逐笔承诺、实际发生、止损收尾和转正。提前开工批准不自动通过 DG-01 或 DG-02。

## 2. 范围与页面

项目内提前开工申请、审批轮次、有效范围与限额、最小承诺台账、安全收尾授权和转正历史。顶部展示有效期限、风险负责人、承诺/实际/剩余额度；范围、停止条件、缺项和补齐计划持续可见。金额与人时独立，不把人时折算货币。

## 3. 流程

申请明确范围条目、人时/费用上限、开始结束日、风险负责人、停止条件、未齐备项与转正计划 → 独立授权人批准/退回 → 范围内逐笔承诺和实际核销 → 到期/停工/超额冻结新增承诺 → 必要安全收尾获得额外限额与期限 → 正常商务依据补齐并通过 DG-01 后显式转正，DG-02 另行批准。

## 4. 业务规则

申请保存草稿或提交；每次提交形成不可变评审快照，退回后改原对象再形成新轮次。批准额不得高于申请额，人时和费用至少一项大于零，期限有效；审批人须启用项目成员且不同于提交人。同项目只有一份未关闭的已批准申请，禁止叠加申请绕过限额。已批准范围不原位扩充；确需调整先关闭原申请、保留承诺，再重新独立申请。

承诺类型 LABOR/PROCUREMENT/SUBCONTRACT/OTHER，范围必须选择批准的范围条目。逐笔记录责任人、实际发生日期、金额/人时、说明和依据。新增承诺要求当前日期与记录日期都在授权期、未停止、范围一致；总占用＝未核销承诺＋累计实际，不能超过批准额。实际可部分核销同一承诺，不能核销超额或跨申请；未核销部分继续占用。冲正保留原记录且防重复，已有有效实际核销的承诺不可直接冲正。

到期禁止新增普通承诺，允许补录原批准期内已发生实际。直接实际超出批准额必须说明原因，形成超限提示并持续冻结新增承诺，不能为了余额好看而阻止记录已发生事实。非批准范围或日期的发生须经受控例外，不混入正常承诺。安全收尾由另一名授权人明确范围、原因、限额与新期限；只允许原批准范围内的止损/收尾，独立计算例外占用并保留审批人。关闭不删除台账、不免除未核销承诺。

转正须引用同项目当前有效 DG-01 包，并有合同/中标通知/委托函正常商务依据；仅引用提前开工自身的包不能自证转正。转正后停止临时新增承诺，旧实际与核销历史永久保留。DG-02 不因此自动通过。

## 5. 状态

申请 DRAFT/SUBMITTED/RETURNED/APPROVED/CLOSED/REGULARIZED；有效性从日期、上限、停止状态计算 ACTIVE/NOT_YET_ACTIVE/EXPIRED/OVER_LIMIT/STOPPED。账目 COMMITTED/ACTUAL/REVERSAL，冲正原行 retained。审批轮次不可更改历史内容。

## 6. 查询

项目内申请历史与台账；按类型、范围、责任人、是否冲正查找。EARLY_START_READ 只看授权范围/上限/汇总；EARLY_LEDGER_READ 才返回逐笔费用及依据。

## 7. 展示字段

申请号、范围条目、临时上限、授权期、风险责任、缺项、停止条件、转正计划；累计承诺、实际、未核销与剩余；每笔类型、日期、责任、依据、原承诺/冲正关联；授权人与历史轮次。

## 8. 表单

申请、提交/复核、承诺/实际/冲正、安全收尾授权、关闭、转正。保存失败保留字段，范围为已有条目选择，实际核销只展示同申请有效承诺；提交按钮依服务端状态和权限展示。

## 9. 异常

并发超限在项目锁下校验，重复请求不重复入账。无权限、关闭项目、跨项目、旧版本、自审、超范围、新增超额承诺和过期新增承诺拒绝。无明细权限不返回台账正文、费用依据或人员记录。

## 10. 数据与权限

Handover 模块独占 early_start_application、early_start_review、early_start_ledger、early_closure_allowance；权限 EARLY_START_READ/EDIT/REVIEW、EARLY_LEDGER_READ/EDIT。审批/关闭/例外权限独立于录入权限，项目角色默认不获得审批或明细读取。

## 11. 功能详细设计

`/api/projects/{id}/early-start` GET/POST；`/{applicationId}` PATCH；`/submissions`、`/reviews/{reviewId}`、`/ledger`、`/closure-allowances`、`/close` POST；转正由 `/handover/early-start/{applicationId}/regularize` 验证当前移交包后调用公开接口。命令使用 requestId/实体 version，项目锁防并发绕限额。LedgerPolicy 用 BigDecimal 计算原承诺减核销与实际占用。批准时保留当轮申请快照，审核不得静默调整范围或延长期限。

## 12. 验收

独立批准、期限与范围、金额/工时各自上限、并发超额、部分核销、冲正顺序、到期补录实际与冻结新承诺、超额实际提示、单独安全收尾限额、只读明细隐藏、正常 DG-01 转正、阶段隔离、响应式真实操作。

## 13. 待确认

真实公司授权阈值与止损人员范围由角色规则配置。首批以明确独立授权执行，不根据金额自动批准、不代替采购、分包和付款审批。

## 14. 变更

v0.1：有限开工依据、最小承诺台账、到期控制与转正，2026-09-12。
