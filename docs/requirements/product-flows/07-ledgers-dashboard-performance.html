需求方案 07｜管理台账与角色化看板

业务过程是源，台账和看板是结果；业务结果从商机与项目空间自动回显，绩效管理当前暂缓。

分批边界：P1 只实现商机台账、项目空间台账、商务管理看板和管理层商机看板；交付/资源台账随 P2/P3 深化，经营报表属于 P4，车辆、宿舍、保险等辅助台账暂缓。
一、台账从业务自动形成
业务事件
商机、售前立项、业务结果、移交、阶段、清单、人员承诺、采购、验收与维护
→
项目台账
人员配置
采购台账
车辆台账
宿舍台账
保险台账
备品备件
工具与资产
例：项目人员在飞书完成出差审批后，系统关联项目编号、人员和日期；现场住宿、车辆和保险记录再补充项目专属信息，人员配置台账随之自动更新。
二、通用资源台账使用同一套生命周期
登记
编号、类型、归属
分配
项目、人员、期限
使用
位置、状态、记录
异常
损坏、缺失、到期
归还 / 续期
验收、维护、费用
报废 / 关闭
原因、审批、凭证

车辆、工具、保险、住宿和备件的专属字段不同，但项目、责任人、时间、状态、费用、附件和提醒机制可以复用。

三、同一数据形成三层看板
项目看板
主阶段、当前重点阶段、并行阶段、状态、结果、里程碑、项目清单、需求、风险、问题、成员和资金摘要
部门看板
人员负荷、跨项目任务、专业交付、逾期问题、质量缺陷、未来资源需求
公司经营看板
商机/项目组合、业务结果、优先级、进度风险、收入回款付款、成本偏差、重大决策项
四、后续月度工作视图｜不是绩效评分
项目任务
从主计划和工作包自动带入
＋
部门与专项工作
产品建设、培训、制度、临时专项
→
个人月度工作视图
目标、任务、成果和完成事实
不设置绩效权重或评分
五、绩效管理当前暂缓
不纳入当前 MVP
绩效考核表、KPI/OKR、评分、校准、申诉和奖金联动均不在本阶段设计。系统只保存真实、可审计的业务过程事实，未来如有需要再单独立项。

台账支持筛选、导出和权限视图，但不得通过导出的Excel形成新的线下主数据源。
