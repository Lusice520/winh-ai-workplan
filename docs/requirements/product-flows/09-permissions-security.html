需求方案 09｜组织、账号、权限与数据安全

系统先建立可管理的组织与账号，再联合计算系统角色、组织范围、项目/阶段角色、数据密级、记录状态和临时授权；加入项目不等于获得全部敏感信息。

一、实际权限由五类条件联合计算
① 系统角色＋组织范围
决定通用菜单、操作，以及本人/本部门/授权组织的数据范围
② 项目＋阶段角色
项目经理、售前负责人、阶段负责人、成员等
决定项目内职责权限
③ 数据密级
一般、项目内部、商务敏感、核心技术
决定字段与文件可见范围
④ 数据状态
草稿、评审中、已批准、已归档
决定可编辑、可下载和可替换范围
⑤ 临时授权
限定对象、动作和期限
到期自动失效并完整留痕
权限结果：系统按对象和动作联合判断菜单、记录、字段、文件查看、下载与分享；管理员可预览指定用户对指定对象的实际权限及主要来源。
二、账号与项目成员生命周期
建立身份
创建或导入用户
启用账号
验证身份并允许登录
授予角色
系统角色＋组织范围
加入项目
项目角色＋阶段角色
责任交接
调动、换任和未完事项
停用回收
锁定、离职或停用
历史保留
责任、操作和审计不删除
边界：这里只维护系统身份、组织归属、账号状态和责任关系，不建设考勤、薪酬、绩效或完整人事档案。
三、主要角色的数据视角
商务 / 售前
商机、客户、合同、移交，以及参与项目的资金摘要、风险、问题和成员
成本、采购价格、利润和内部费率默认隐藏
项目经理
计划、资源、风险、预算执行、交付资料
不能查看个人薪酬等无关敏感数据
工作包负责人 / 成员
本专业任务、资料、问题和必要接口
按需查看相关成本与采购状态
部门负责人 / PMO / 管理层
部门资源、项目组合、重大异常和经营汇总
管理层按授权穿透敏感信息
采购
采购需求、预算校验结果、供应商、合同和到货
不修改技术验收结论
财务
预算口径、付款节点、开票、实际成本和对账
不修改项目执行进度
知识库管理员
目录、模板、发布与归档规则
不自动获得所有敏感文件内容
系统管理员
组织账号、角色权限、字典规则和集成配置
不自动获得敏感业务数据
四、敏感数据分层
L1 一般项目资料
计划、普通任务、公开手册
项目成员按角色查看
L2 项目内部
现场资料、设计过程、问题记录
限定项目成员
L3 商务/经营敏感
合同价格、利润、采购价格、回款与预算明细
按授权角色查看
L4 核心技术/严格限制
核心算法、源代码、密钥与受控图纸
最小范围、下载控制与全量审计
五、两种互联网访问路径
公司员工登录
仅公司员工建立账号；使用统一身份、会话/设备控制、操作审计和离职即时停权访问完整系统。
文件分享链接＋密码
只有同时具备目标文件查看/下载权和对应密级分享权的员工才能生成；访问者无需系统账号，且只能访问所选文件。支持有效期、主动撤销、查看/下载方式和访问日志；首期所有文件类型技术上可分享，不增加额外审批。

客户、供应商和分包商不建立项目空间账号。分享链接主要用于员工互联网受控访问，不开放项目目录或空间权限；如确需对外提供资料，由员工下载后自行发送。

六、项目经营信息可见性边界
项目经理应看到
批准预算、已承诺、实际成本、完工预测、成本分类和偏差；足以承担项目经营责任。
项目经理默认不看到
个人工资、公司内部费率明细、无关供应商底价及其他项目的敏感经营数据。
售前保留查看权：参与项目的资金计划与实际摘要、风险、问题、成员可见；成本明细、采购价格、利润和内部费率不可见，除非另行授权。

已批准或已归档数据原则上不可直接修改；需要更正时通过变更或冲销机制保留原记录。
