需求方案 08｜主阶段、并行执行阶段与项目模板

P2 在原项目空间完成 DG-02 交付立项与项目基线；通过后同一批对象转为批准基线，再由 P3 沿用执行。

P1/P2/P3 边界：P1 的 DG-01 只形成交付可接收移交包。P2 从该移交包接续，先开放团队、执行阶段、项目清单、专业工作包、主计划和预算草案用于准备 DG-02；DG-02 通过后同一批对象转为批准基线、主阶段变为“交付”。P3 沿用该基线开展完整执行，不重复建对象。

一、交付主流程｜阶段内可并行，阶段门控制关键成果
① 交付立项与基线
项目组、执行阶段、项目清单、启动会、主计划、工作包、实施预算
DG-02：交付立项与项目基线批准
② 深化调研与需求
在售前调研基础上完成现场踏勘、正式资料包、接口与验收边界
DG-03：深化需求基线确认
③ 设计与评审
机械、电气、软件、验收标准；内部评审与必要的外部确认
DG-04：设计基线与采购/开发放行
④ 采购与开发
采购执行、机械电气制造、PLC、通用软件、算法与接口开发并行
DG-05：出厂/进场就绪
⑤ 到货与测试
到货验收、软件测试、接口测试、FAT、缺陷关闭
DG-06 前置：到货验收、软件/接口测试与缺陷关闭
⑥ 安装与配置
安全准入、技术交底、施工、通电通网、设备配置与完工复核
DG-06：调试条件具备
⑦ 调试与试运行
按范围启用手动、半自动、全自动、ECS；空重载记录、培训与试运行
DG-07：验收就绪
⑧ 验收与交付复盘
验收会、签署、归档、离场、交付复盘与维护移交
DG-08：验收归档与维护移交；DG-09 暂缓

基线不是永久不变：到货、测试或现场阶段发现问题时，项目保持当前主阶段，只对受影响的执行阶段、项目清单项、工作包、采购项和验证活动开启变更分支；批准后发布新版本并保留替代历史。
三、调试能力按合同范围逐级启用
远程手动
前置条件、安全培训、接口准备、空重载调试记录
远程半自动
流程组合、空重载验证、异常与人工接管
远程全自动
自动作业流程、效率、安全联锁与重载验证
全流程 ECS
系统间协议、PLC联调、流程级异常与全链路记录

未纳入合同或项目范围的等级不生成强制任务；已启用等级必须满足自己的前置条件、测试用例和通过证据。

六、DG-02 角色、消息与审计
责任不混用
项目经理组织和提交/撤回；技术及工作包负责人确认专业内容；部门负责人承诺资源；PMO组织治理检查；授权人按配置通过/退回。系统管理员不因配置权限取得业务批准权。

具体会签部门、金额阈值、重大变化触发复审的规则在 P2 试点前配置确认；页面不把尚未确认的组织假设写死。

PMO Excel V0.1 只作为原始动作来源继续校正，不直接成为当前执行基线；P2/P3 的后续 SPEC 决定哪些项目必须执行、由谁执行以及怎样证明已经完成。
