# TC-007：菜单与权限管理验收用例

> 状态：本地验收通过（2026-09-13；最终记录见 ACCEPT-007，历史执行记录保留）  
> 关联工作项：[WI-007](../work-items/WI-007-menu-permission-management.md)  
> 关联需求：[SPEC-IAM-02](../../requirements/specs/role_permission_spec.md)、[IAM Foundation Contract](../../technical/designs/shared/IAM_FOUNDATION_CONTRACT.md)  
> 执行环境：本地 PostgreSQL、Spring Boot、Vite；不使用 Mock 授权数据

## 前置条件

1. 已完成 WI-006，存在可登录的权限管理员与至少一个非管理员测试账号。
2. 菜单资源、权限项、角色、数据范围和临时授权的正式决策规则已经冻结并迁移到本地 PostgreSQL。
3. 所有请求通过真实 Cookie 会话、CSRF 和服务端授权判断；浏览器中的可见性不作为授权证据。

## 验收矩阵

| 编号 | 场景               | 操作                                                                                 | 预期结果                                                                         |
| ---: | ------------------ | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
|    1 | 菜单资源注册       | 新建目录、菜单页和操作资源，填写编码、父级、受控 `routeKey`/动作键、图标、排序和状态 | 资源编码唯一；层级和受控键规则可定位字段；任意 URL/动作被拒绝；保存后写变更审计  |
|    2 | 已引用资源治理     | 给资源授权给角色后尝试删除、停用或调整层级                                           | 不允许物理删除；停用前显示角色/导航影响；历史引用与审计仍可查看                  |
|    3 | 权限项目录         | 为菜单、操作、数据范围、敏感字段、文件查看/下载/分享和配置动作建立权限项             | 各维度可独立授权；只授予菜单可见不会自动允许业务动作                             |
|    4 | 角色分层           | 分别新建系统角色、项目角色模板和阶段角色模板                                         | 类型不可混淆；项目/阶段角色不自动成为系统角色或项目成员                          |
|    5 | 系统角色授权       | 在独立授权页为启用账号分配和撤销启用系统角色，再尝试越级或停用对象分配               | 用户表单不含角色编辑；越级、停用账号或停用角色分配被服务端拒绝                   |
|    6 | 权限矩阵与数据范围 | 为角色配置资源、动作、组织/项目/对象范围、字段和文件条件                             | 保存的每项可解释；范围仅取冻结枚举；不兼容组合和超出授予人可下放范围被拒绝       |
|    7 | 硬约束拒绝优先     | 为同一用户配置多个角色或有效临时授权，再令账号、资源、范围、状态或密级条件失败       | 正向允许可以并集；任一硬约束失败仍 `DENY`，且解释链给出脱敏原因                  |
|    8 | 角色状态和影响     | 编辑已引用角色、收缩权限或停用角色                                                   | 保存前显示影响数量；新分配被阻止；历史权限和审计结论不被改写                     |
|    9 | 临时授权           | 创建最小对象范围的普通/高敏感临时授权，尝试超时，再提前撤销并分别验证到期            | 原因和时间必填；普通不超过 7 天、高敏感不超过 24 小时且需复核；全程可追溯        |
|   10 | 权限预览           | 选择用户、业务对象和目标动作，分别验证允许与拒绝                                     | 返回即时允许/拒绝和解释链；不泄露无权业务对象内容                                |
|   11 | 动态导航一致性     | 分别以两个角色登录，刷新 AppShell，再直接请求受限业务 API                            | 只显示启用且已注册 `routeKey` 的 `listNavigation` 结果；HTTP 绕过仍被拒绝        |
|   12 | IAM-01 迁移回归    | 使用正式安全管理员访问组织/用户管理，并以普通账号尝试访问                            | 正式 `decide(...)` 控制访问；桥接分支已删除；用户表单仍没有角色/菜单/权限编辑项  |
|   13 | 审计与安全         | 复核菜单、角色、授权、临时授权、拒绝和过期事件                                       | 审计包含动作、操作者、对象、时间、结果和脱敏摘要；不包含密码、会话令牌或无权数据 |
|   14 | 数据库与跨端回归   | 运行 Flyway、后端 Module/HTTP、前端类型/lint/test/build和浏览器流程                  | 所有检查通过；刷新后数据来自 PostgreSQL；不存在 Mock 授权数组或静态白名单兜底    |

## 通过条件

所有 14 项均有自动化结果或可复现的浏览器/HTTP证据。若“导航显示正确”但直接请求接口未被拒绝，或“角色/临时授权显示允许”但硬约束未拒绝，则本用例整体不通过；这说明菜单和服务端授权没有使用同一决策事实。

## 最终执行记录（2026-09-13）

14 项验收矩阵已有模块/HTTP/浏览器证据，本地验收通过。原“等待确认本地授权写入”的限制由用户持续的整套系统实施授权承接，使用合成对象完成，不涉及外部人员。

- 本地实际接口的 5 组检查见 `outputs/verification/wi-007/api-checks.json`；目录唯一性、受控键、角色分层、越级拒绝、临时授权及正向权限合并均已验证。
- 页面分配只读角色后，受授人用户目录返回 200 且无新增/编辑入口；页面收回后入口消失、HTTP 返回 403，原业务员工角色与撤销历史保留。
- 高敏感临时授权在 `PENDING_REVIEW` 时合同敏感内容不可见；指定独立复核人从页面批准后可见，起止时刻与对象范围未变；页面撤销后立即不可见。申请人/受授人不能代为复核，拒绝及精确到期由接口/集成测试覆盖。
- 菜单资源的真实修改和停用完成，保存前可读取子资源、权限项、角色授权与临时授权影响。根目录只改名不发送移动请求，不强行要求移动原因。
- 角色修改/停用和空授权集撤回不能用较低的新级别绕过原角色控制；同级新增被拒绝。高敏感审批前再次检查原授予人的当前权限。
- 删除初始化权限桥接后，24 项后端测试通过；现有库与全新库的正式管理员创建用户成功，未注册权限与硬约束均未被绕过。
- 前端构建、静态检查与交互测试通过。390px 下临时授权记录完整可读，最终截图采用动画结束后的稳定状态。
