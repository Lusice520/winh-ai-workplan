# TC-006：本地登录与组织用户管理关键闭环

> 类型：功能 / 权限 / 异常 / 回归  
> 优先级：P0  
> 关联 SPEC / WI / BUG：[SPEC-IAM-01](../../requirements/specs/organization_user_account_spec.md)、[WI-006](../work-items/WI-006-login-user-management-local.md)  
> 适用版本与环境：本机 PostgreSQL、Spring Boot 后端、Vite 前端；使用已忽略 `.env` 的初始化管理员配置

## 1. 验证目标

- 验证登录、会话、账号状态、组织/部门与用户管理均使用真实 API 和 PostgreSQL；
- 验证安全边界不会泄露账号状态、不会保留失效会话，也不会把角色/菜单 Mock 当作正式权限功能；
- 验证页面能完成已确认的块状单字段表单与可用分页交互。

## 2. 前置条件与测试数据

- 账号与角色：一个由安全环境变量创建的初始化系统管理员；一个普通启用用户；
- 初始数据：一个根组织、至少一个启用部门；可额外创建一个停用部门；
- 配置与环境：PostgreSQL 已启动，Flyway 已执行，前后端均通过本地运行时启动；
- 测试数据是否已脱敏：是；不记录真实密码、Cookie 或会话令牌。

## 3. 执行步骤

| 步骤 | 操作                                                                            | 预期结果                                                                                   |
| ---- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 1    | 使用不存在账号、错误密码、停用账号和锁定账号分别登录                            | 页面均显示同一中性提示；不泄露账号是否存在或状态                                           |
| 2    | 使用初始化系统管理员正确登录                                                    | 进入组织与用户；`/api/auth/me` 返回当前账号摘要，浏览器不读取会话 Cookie                   |
| 3    | 连续输入错误密码 5 次，再以正确密码登录                                         | 账号被锁定 15 分钟；外部提示仍为中性认证失败；审计保留受限失败摘要                         |
| 4    | 以管理员在启用组织中新建部门和用户，并为用户设置临时密码                        | 树和目录通过真实 API 刷新；账号唯一性、字段错误和停用组织校验正确；新用户首次登录要求改密  |
| 5    | 修改用户资料、调动到另一启用部门，并刷新页面                                    | 当前组织更新，组织归属历史保留；旧版本提交得到明确冲突而不覆盖最新内容                     |
| 6    | 停用、锁定、离职和重置密码其中任一已登录账号                                    | 该账号全部已存在会话立即失效，受保护 API 返回 `401`；状态和原因进入历史与审计              |
| 7    | 尝试处理唯一初始化系统管理员的停用、锁定、离职或降级                            | 服务端拒绝，页面给出可操作说明；数据无变化                                                 |
| 8    | 在用户表格切换页码和“每页条数”下拉项                                            | 发起真实分页请求；下拉层稳定可见、不贴边、不抖动，表格数据与总数同步                       |
| 9    | 打开新建部门、新建用户与状态变更抽屉                                            | 单行字段为左标签右控件且每行一个字段；多行原因在上方标签、全宽输入；区块之间有可辨识间距   |
| 10   | 检查侧栏与用户表单                                                              | 不出现可编辑的角色、菜单或权限设置；这些能力仅在后续 IAM-02 中交付                         |
| 11   | 以初始化管理员提交缺失、过期或无效 CSRF 的写请求，再以普通用户访问 IAM 管理接口 | 前者为 `403 CSRF_VALIDATION_FAILED` 并保留表单、允许再次提交；后者才为 `403 ACCESS_DENIED` |

## 4. 结果记录

> 结果：通过（本机实现、自动化与真实浏览器“新建用户”闭环均已完成）

- 实际结果：本机管理员已通过真实登录页进入组织与用户页面；已在浏览器中创建一条清晰标识的本地验收部门。受控 API 闭环已完成 CSRF 获取、登录、组织树查询和用户创建，用户创建返回 `201` 且首次登录要求改密；该用户已在真实浏览器目录中回显。
- 本次缺陷修复：已复现并修复 CSRF 失效被误报为账号无权限的问题；初始化管理员缺少 CSRF 时现返回可恢复的 `CSRF_VALIDATION_FAILED`，普通用户仍为 `ACCESS_DENIED`，无数据写入。
