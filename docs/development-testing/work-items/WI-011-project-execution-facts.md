## 1. 目标与验收

在 DG-02 批准的同一阶段、清单、里程碑上追加实际记录，明确计划与实际的差异；现有 DONE 工作和基线历史保持原事实。

1. 项目经理控制阶段开始、暂停、恢复、完成、重开；阶段负责人维护实际进展与证据，不改变主阶段；前置关系和完成条件有实际检查。
2. 原清单明确适用的到货/安装环节、品牌型号供应商，按实际日期、数量、依据登记分批到货和安装；验收由指定其他人验证，数量守恒且不能超批准范围。
3. 实际记录更正通过留痕冲回，保留原记录、原因和操作者；已有下游验收时先明确处理下游，不悄悄改历史数量。
4. 里程碑实际完成有日期、证据及指定独立验证，待验证、已验证与计划日期分别呈现；不自动修改合同节点或生成经营实际。
5. 基线调整不能把已有执行量变成合法超范围或直接删除有实际事实的对象；受影响验收需明确重新验证，历史版本和责任可追溯。
6. 命令实时检查实际角色、项目状态、当前对象/执行版本、文件读取和成员有效性；重放不重复、并发失败整笔回滚；跨项目拒绝。
7. 固定“项目阶段/里程碑/项目清单”入口及原工作包详情可直达执行，紧凑展示当前基线、实际、差异和最近事件；桌面/390px 及多账号浏览器验证。
8. 对应自动测试、真实 PostgreSQL 流程、重启/空库迁移、类型/Lint/构建通过，并同步 TC/ACCEPT 与共享契约。
