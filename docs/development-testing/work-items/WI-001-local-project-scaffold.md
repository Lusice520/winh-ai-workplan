## 1. 目标与结果

建立可在本机启动的 React 前端与 Spring Boot 后端最小骨架，使用真实组件验证页证明 shadcn/ui + Base UI 路线能承担本项目的表格、表单和常用后台交互，并跑通前端 `/api` 代理到后端健康接口。

## 2. 范围与非目标

### 本次范围

- 锁定 Node、pnpm、Java、Spring Boot 和主要前端依赖版本；
- 创建 `apps/web`、`apps/backend`、`infrastructure/local` 和必要的根目录工程配置；
- 创建无业务承诺的 `component-lab`；
- 建立最小前后端测试、构建和本地启动说明；
- 在真实运行结果基础上固化前端共享组件规则。

### 本次不做

- 不实现正式登录、账号、权限、会话和数据库表；
- 不安装或配置 PostgreSQL、MinIO、NAS、VPN、域名、证书和生产部署；
- 不推送 GitLab，不建立远程分支和合并请求；
- 不把组件验证页冒充正式产品页面；
- 不并用 Ant Design、HeroUI、MUI 或其他完整 UI 体系。

## 9. 风险与回退

- 已知风险：shadcn/ui + Base UI 需要项目自建 DataTable 与表单模式，初始投入高于 Ant Design；
- 控制方式：先做 `component-lab`，以可运行结果评估，不在业务页面中试错；
- 回退方式：骨架阶段没有业务数据。若后续关键路线验证失败，保留 Vite/React 架构，通过新 ADR 迁移组件层，不长期并存两套默认 UI；
- 初始化偏差：shadcn 官方 Registry 在当前网络超时，因此按官方 Base UI 结构手工建立 `components.json`、Token 和首批项目组件；运行时依赖、源码所有权和验证结论不受影响；
- 已修复问题：Dialog Trigger 的中间组件未透传 Base UI 事件，浏览器点击无响应；改为由可转发属性与 ref 的项目 Button 直接承接后通过；
- 已知构建提示：当前 Mockito 测试在 Java 21 会提示动态加载 Byte Buddy Agent 的未来兼容警告，测试仍全部通过；升级 JDK 或 Mockito/Spring Boot 时要按官方方案改为显式 Agent 或验证新版默认行为；
- 未验证项：复杂树、甘特图、大规模虚拟表格、正式文件上传、严格 CSP、屏幕阅读器和公司实际浏览器版本。
