## 1. 目标

在当前项目接续 DG-01，通过团队资源、发布模板快照、阶段、里程碑、清单、工作包、计划与实施预算的完整准备和独立评审形成 DG-02 V1 基线。批准前主阶段仍为售前，批准后保留对象 ID 转入交付。

## 2. 范围与所有权

当前 Codex 独占新增后端 `delivery/`、前端 `features/delivery/`、相关测试；串行维护项目/工作包公开接口、项目空间固定入口、业务导航与权限注册、共享 API 类型、V11 起前向迁移和本地验证脚本。文档为 PRD 清单中的八份对应 SPEC、共享契约、TC/accept、README 和前后端导航。V1–V10 不改写。先完成对应详细规格再实现功能；所有本地合成账号和数据有明确验证标记。

公司金额阈值、部门决策映射和阶段模板不从示例推定为正式制度。采用明确配置的发布模板、指定资源承诺人与具有业务权限的独立评审人；无配置时显示缺项。财务采购触发顺序仍待答复，不阻塞本 WI。未经授权不 commit、push、MR 或部署。

## 3. 验收标准

1. “交付立项”独立系统入口汇总已完成 DG-01 的原项目；准备工作不提前切换主阶段。
2. 团队关键责任明确，资源申请需本人或指定有权承诺人确认；冲突有显式结论，换任保留历史及权限边界。
3. 阶段模板草稿/发布版本独立；项目引用发布快照，适用性与跳过/新增理由、责任、依赖、并行与完成依据完整；发布新版不覆盖项目。
4. 非空里程碑、清单、工作包和主/工作包计划互相关联；日期、依赖、责任、验收和采购需求能真实校验，已有需求派生工作包保留 ID 和原链接。
5. 预算覆盖资源与采购；分阶段授权记录范围、上限、有效期和补齐时间；金额服务端按权限隔离。
6. 九组准入检查及遗留事项阻断规则可复现；无法完整核验权限与业务缺项分别提示，不以绿色示例代替真实校验。
7. 提交保存不可变轮次和快照；独立会签/最终审批，禁止自批；退回/撤回/重提保留意见和对象 ID；评审期间冻结被引用对象。
8. 通过后原对象标记 V1 并进入交付，重试不重复生效；非阻断遗留项按责任人提交证据、指定他人验证，显示期限/逾期/升级。
9. 后续里程碑与预算由有权项目经理说明理由后产生直接生效的新版本；其他实质基线变更经明确有权确认，历史不可覆盖，不整体回滚项目。
10. 验证权限/跨项目/独立审批/对象冻结/并发与重试/退回再提/源版本变化/重启持久化/新库迁移，以及桌面和 390px 真实浏览器流程。

## 4. 验证方式

有意义的后端规则与 HTTP 测试、前端类型/Lint/格式/测试/构建、真实 PostgreSQL API 流程、两名以上合成业务账号完成浏览器审核闭环；正式结果进入 TC-010 与 ACCEPT-010，未执行项不得标记通过。draw-ui 设计稿先查看，再按同视口校准实现。

## 6. 本地实施与验证记录（2026-09-13）

八份对应规格已建立。配置发布/版本、DG2 原对象准备、资源承诺、遗留、冻结轮次和独立批准、原对象基线修订已实现。新增 V11–V13 前向迁移；已应用版本不再改写。前端新增独立交付立项入口、紧凑总览、资源/工作包/遗留/评审页、只读快照抽屉，并在原项目中增加阶段、里程碑与计划、清单和预算固定视图。字段、查询权限与命令权限由服务端继续核验。

真实合成项目已从 SG-01 经文件发布和 DG-01 完成三阶段、三原工作包的准备；真实浏览器完成资源签认、第一轮退回、原对象补齐、第二轮独立会签及公司批准，形成 V1。负责人提交遗留证据、另一指定人验证关闭；项目经理预算修订形成 V2（481,000 元），阶段范围由独立授权人确认形成 V3。旧轮次、V1/V2 快照、源需求链接与工作包 ID 均保持不变。主库重启读回与新库 V13 迁移通过。桌面和 390px 设计校准、手机编辑及签认已有证据，详细见 TC-010。

批准后责任交接已实现并经真实浏览器验证：全量预览未结职责、新人接收、指定人重签资源、项目经理统一生效并回收原成员角色；接任人随后完成原工作包、指定验证人独立验证，原需求不自动关闭。V14–V15 前向迁移通过。责任交接串行维护项目成员/角色公开接口、Work 和 Requirement 未结职责贡献接口，保持权限下放和独立验证约束。

成组新增范围依据 SPEC-DG2 v0.2 实施：独立草案保存阶段/里程碑/清单/工作包/计划/预算/资源差异，提交冻结提案、指定资源重签、独立批准一次生效。允许串行增加 V16 起对应存储，以及 WorkDirectory 的受信批准接纳接口；实际执行仍在原 Work 记录中，不创建第二个项目。

上述成组范围现已实现。真实浏览器完成新提案、两项资源重签、第一轮退回、原候选工作包补齐验收、第二轮独立批准：七个对象、两项资源、499,000 元预算一次形成 V4；批准前执行仍用 V3，新工作包未进入执行，批准后原预留 ID 成为实际 Work。旧 V1–V3、已完成包、原需求和责任交接不变。V17 记录实际草案维护与命令说明，不补造此前不存在的事件；敏感说明与预算均由服务端投影。

最终全套后端 49 项和前端 37 项、类型/Lint/格式/构建通过。全新空库从零表应用 V1–V17，JPA 校验与健康检查通过；主库重启后 V4、两轮提案、已完成工作与旧快照再次读回通过。对象修订抽屉显示逐版前后事实且无编辑字段。桌面范围页改为双列内容卡片，390px 保持单列，手机签认、前后对照、说明历史和新增工作包详情均有实际查看证据。
