## 1. 目标与结果

在不购买商业组件或模板的前提下，将本地前端组件候选切换为 Ant Design v6，并通过可运行的视觉原型验证：定制主题能否满足项目视觉要求，免费核心组件能否覆盖登录、工作计划列表和工作计划编辑三个代表性场景。

本工作项结束时必须形成明确结论：接受 Ant Design v6 为默认组件体系，或者回退到 WI-001 的 shadcn/ui + Base UI 基线。不得长期并存两套默认 Button、Form、Table、Dialog、反馈和主题系统。

## 2. 范围与非目标

### 本次范围

- 锁定并安装 `antd@6.6.1`，移除只服务于旧组件基线的直接依赖；
- 建立项目级 Ant Design Theme Token、中文语言环境和统一反馈入口；
- 在现有 `/component-lab` 路由建立三个结构明显不同、可通过 `?variant=` 切换的视觉方向；
- 每个方向可检查登录、工作计划列表和工作计划编辑场景；
- 验证 Form、Table、Upload、TreeSelect、Steps、Timeline、Modal、Drawer、Notification 等免费核心能力；
- 同步 ADR、总体技术方案、前端共享组件规范、README 和本地运行说明；
- 运行类型、Lint、格式、测试、生产构建和真实浏览器验证。

### 本次不做

- 不实现正式账号登录、会话、权限、数据库或后端业务接口；
- 不引入 HeroUI Pro、商业模板或其他付费依赖；
- 不引入第二套完整运行时 UI 组件库；
- 不承诺原型中的字段、文案、数据或页面结构是正式产品设计；
- 不引入 Ant Design ProComponents，除非后续独立确认其必要性、版本兼容和维护状态；
- 不提交、推送、创建 MR 或部署。

## 9. 风险与回退

- 已知风险：Ant Design 会带入完整运行时和默认交互结构；过度深层 CSS 覆盖会增加升级成本；
- 控制方式：优先使用全局 Token、Component Token 和 v6 语义 `classNames/styles`，不依赖不稳定的内部 DOM 选择器；
- 已知风险：Ant Design v6 较旧版本升级了 React、浏览器和部分 API 要求；
- 控制方式：当前 React 19 和现代浏览器目标满足前提，依赖使用精确版本并通过 lockfile 复现；
- 回退方式：当前没有正式业务页面或业务数据；若视觉或关键交互不通过，移除 Ant Design 依赖并按 WI-001 记录恢复旧基线；
- ProComponents 边界：`@ant-design/pro-components@2.8.10` 当前 peer dependency 只声明支持 antd v4/v5，本次不安装；待官方明确支持 v6 且出现真实需求后再验证；
- 构建体积：生产构建成功，但主入口仍有大于 500 kB 的原始 chunk 提示；正式功能路由形成后建立性能预算并继续拆包；
- 未验证项：公司实际 Chrome/Edge 版本、屏幕阅读器、严格 CSP、甘特图、正式上传链路和超大数据集性能。
