## 1. 目标

同一项目空间接续签署后合同主档、综合管理归档、真实文件版本和 DG-01 交付准入；合同签署、商机结果、提前开工、DG-01 与 DG-02 分别留存。页面继续使用 draw-ui 和 WI-008 已验证的紧凑视觉体系。

## 2. 范围与所有权

当前 Codex 独占新建 `apps/backend/.../{contracts,files,handover}/`、对应测试、`apps/web/src/features/{contracts,files,handover}/`；串行维护公开 `ProjectDirectory`/`CrmDirectory`、权限注册、路由、共享前端类型/API 客户端、V7 起前向迁移、S3 适配依赖和本地运行脚本。文档范围为对应 SPEC、共享技术契约、TC/accept、导航上下文及 README。既有 V1–V6 不改写。

本地开发的对象存储验证可用仅监听回环地址的 S3 测试服务，二进制与 PostgreSQL 元数据分离；不宣称替代生产存储选型、IT/许可证审查或备份容量验收。对外分享的隔离公网入口未配置时不得假称已发布。未授权 commit、push、MR 或部署。

## 3. 验收

1. 合同从原项目和商机登记，编号唯一、签署后事实、金额和日期校验；付款/验收节点及补充、变更、终止关系可追溯。
2. 文件实际上传与受控读取、SHA-256、版本递增、发布/替代/作废、业务关联均可验证。查看/下载/敏感合同字段分别授权，不泄露对象键或凭据。
3. 当前签署件齐备方可提交归档；另一名有归档权的管理人员接收或退回；修改需补充记录，历史不覆盖。人员通过角色配置，不能硬编码小花等姓名。
4. DG-01 缺项可见，必需项关联当前有效成果或文件；提交快照、独立评审、退回重提和不可变移交包。通过不切换交付主阶段。
5. 提前开工范围、上限、期限、风险负责人、停止条件及最小承诺台账受控，不替代合同或 DG-01。
6. 正常/无权限账号、跨项目引用、独立评审、并发、重试、对象存储故障、重启持久化及桌面/窄屏验证。

## 4. 事实与实施顺序

先按 [CT-01](../../requirements/specs/contract_archive_spec.md) 和 [DOC-01](../../requirements/specs/project_files_spec.md) 完成合同与文件；DG-01/提前开工的详细 SPEC 必须先于相应代码。归档≠签约审批，不接入签署、银行或会计系统。财务采购顺序的澄清不阻断本 WI。

## 5. 验证与风险

前后端检查、真实 PostgreSQL 与 S3 协议上传/下载校验、权限/版本/失败恢复、真实浏览器完整归档流程。生产大文件预览、病毒扫描、备份恢复和公网分享隔离仍按 ADR-004/007 单列验收，不能以本地流程通过替代。
