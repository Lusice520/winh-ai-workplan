## 1. 目标与结果

将用户已确认的浅色高密度工作台视觉语言，转化为首批基础管理与主数据能力的可实施产品规格。完成后，团队能够针对组织与用户、角色权限、客户、商机和项目空间分别评审页面结构、数据边界、操作流与验收场景，并按依赖顺序进入后续开发工作项。

本工作项只产出正式需求与页面设计事实，不实现前端、后端、认证、数据库或路由。它不把“系统管理”误写为单页，而是明确其下组织用户与角色权限两条能力线，并保留配置、审计、数据任务等后续系统能力的独立边界。

## 2. 范围与非目标

### 本次范围

- 创建组织、部门、用户和账号生命周期的 `SPEC-IAM-01`；
- 创建系统角色、权限维度、组织数据范围与临时授权的 `SPEC-IAM-02`；
- 创建客户主档、联系人、查重和受控合并的 `SPEC-CM-01`；
- 创建商机建档、等级、销售进展、跟进和主线约束的 `SPEC-OM-01`；
- 创建从商机建立项目空间、项目入口壳层和四类状态一致回显的 `SPEC-PW-01`；
- 将已确认视觉基准写入上述 SPEC 的页面设计，且引用现有 Ant Design v6 组件和主题规范。

### 本次不做

- 不实现登录、会话、权限计算、用户导入、数据库迁移、API 或正式页面；
- 不设计商机结果、关闭、重开、Excel 导入、售前动作、阶段门、合同、审计中心、字典参数或消息待办的完整功能；这些分别由独立 SPEC 承担；
- 不改变已有共享主题、组件库、路由或技术 ADR；
- 不复制参考图片中的品牌、文案、菜单结构或业务数据；它只作为视觉语言参考；
- 不创建 commit、推送、GitLab MR 或部署。

## 4. 前置条件与依赖

- 前置工作项：WI-002 已确定 Ant Design v6 与可丢弃组件验证基线；它不构成正式业务页面设计；
- 上游事实：PRD V0.4 第 2、3、4、6、7、8、9 章及《前端组件规范》；
- 设计输入：用户已选择白色左侧栏、浅蓝灰画布、紧凑顶部上下文、轻量卡片/表格/标签的工作台方向；
- 关键依赖顺序：`SPEC-IAM-01 → SPEC-IAM-02 → SPEC-CM-01 → SPEC-OM-01 → SPEC-PW-01`；其中客户主档是商机必填关联的前置能力，项目空间只能从商机创建；
- 待配置而非待定产品方向：首批组织树、身份认证方式、初始管理员、客户去重键、销售进展字典、停滞时限、系统角色和敏感字段分级。

## 6. 实施步骤

1. 将用户选定的视觉语言转译为五份 SPEC 共用且可验收的页面设计原则；
2. 先完成组织、部门、用户和账号状态的边界，避免角色、商机和项目页面各自假设身份模型；
3. 完成角色和权限维度的产品规则，明确系统角色、项目角色、阶段角色不互相替代；
4. 完成客户和商机的最小建档、查询、详情、查重、跟进与主线规则；
5. 完成从商机创建项目空间和空间入口壳层的规格，不提前实现 P2/P3/P4 内容；
6. 交叉核对 PRD 用词、状态边界、依赖关系、页面状态与验收场景；
7. 评审通过后，按各 SPEC 另立实现工作项，并先处理 `SPEC-IAM-01` 的认证/账号基础设施。

## 9. 风险与回退

- 已知风险：公司实际组织树、认证方式、用户来源、销售进展和角色矩阵尚未配置；SPEC 将其作为实施前配置项，不将猜测固化为业务事实；
- 已知风险：把首批视觉页面当作可直接开发的接口设计，可能绕过安全、数据和权限的详细设计；
- 控制方式：状态保持 `draft`，后续实现工作项必须补齐第 11 章专属技术设计和实现验收；
- 回退方式：本文档均为新增草案，可在评审中修订或删除；未改变现有代码、数据或环境；
- 未验证项：真实用户可用性测试、真实权限矩阵、数据规模、认证供应商、浏览器辅助技术与接口性能。
